# 변경요청서 — 현장 문서 대비 시스템 기준값 불일치 3건

| 항목 | 내용 |
|---|---|
| 문서번호 | CR-STD-001 |
| 제기일 | 2026-08-27 |
| 제기 근거 | 작업표준서 **WS-KS-001** Rev.0 · 품질기준서 **QS-KS-001** Rev.0 (2026-08-27 접수) |
| 대상 | 생산팀 · 품질보증팀 |
| 상태 | **확정 요청** |

---

## 왜 이 문서가 필요한가

현장 문서 2종을 AI Agent 코퍼스에 적재하면서 **시스템 설정값과 현장 문서가 서로
다른 값을 말하는 곳 3군데**를 확인했습니다.

지금 상태로 AI Agent 를 열면, 같은 질문에 **어느 근거를 집었느냐에 따라 다른 답**이
나옵니다. 그리고 그 답은 둘 다 그럴듯합니다. 이게 가장 위험한 형태의 오답입니다.

**어느 쪽이 맞는지는 저희가 정할 수 없습니다.** 현장 기준이기 때문입니다.
아래 3건에 대해 확정을 요청드립니다.

> 시스템 값을 임의로 바꾸지 않았습니다. 대신 작업 표준 문서 본문에 "정본은 현장
> 문서다" 를 명시해 두어, 확정 전까지는 AI 가 불일치를 함께 말하도록 했습니다.

## 1. 품질 「70점」은 합격 판정인가 — **아니오로 정리했습니다. 확인 부탁드립니다**

| | 값 |
|---|---|
| **시스템** | `quality.pass_score = 70` · 70점 이상 pass / 70~80 warning / 80 이상 pass |
| **QS-KS-001 §5.1** | LOT 합부 판정에 **점수 개념이 없음.** 합격 = 성분·치수·외관·중량 전 항목 규격 이내 **그리고** 치명결함 0개 |

### 무엇이 문제인가

시스템의 70점은 **ML 모델이 예측한 값**입니다. QS-KS-001 의 합부 판정과는 **다른
것**인데, 화면에는 둘 다 "품질" 로 표시됩니다.

작업자가 화면의 점수만 보고 출하 가부를 판단할 수 있는 상태였습니다.

또 판정 구분의 개수도 다릅니다.

| QS-KS-001 §5.1 | 시스템 `lots.status` |
|---|---|
| 합격 | pass |
| **조건부 합격(특채)** | — **없음** |
| 불합격 | fail |
| **보류** | — **없음** |
| — | **warning** — 대응 항목 없음 |

특채는 대표이사 또는 고객 서면 승인이 필요한 판정인데 시스템에 자리가 없습니다.

### 요청

- [ ] 시스템 점수는 **참고 지표**이고 합부 판정은 검사성적서를 따른다 — 이 정리가 맞습니까?
- [ ] `lots.status` 에 **조건부 합격(특채)** · **보류** 를 추가할까요? (화면·API 영향 있음)
- [ ] `warning` 은 QS-KS-001 의 어느 판정에 대응합니까? 대응이 없다면 이름을 바꿔야 합니다.

## 2. 성분 기준값 Sn 62.0 / Ag 3.0 / Cu 0.5 — **어느 합금과도 다릅니다**

| | Sn | Ag | Cu | Pb |
|---|---|---|---|---|
| **시스템 기준값** | 62.0 | 3.0 | 0.5 | (잔부 ≈ 34.5) |
| QS-KS-001 [표 3-3] **SAC305** | 잔부(≈96.5) | 2.8~3.2 | 0.4~0.6 | ≤ 0.07 (사내) |
| QS-KS-001 [표 3-2] **Sn63Pb37** | 62.5~63.5 | — | — | 잔부 |

### 무엇이 문제인가

시스템 기준값은 **유연 계열과 무연 계열을 섞은 조성**입니다. Sn 62 · Pb 34.5 는
유연 쪽인데 Ag 3.0 · Cu 0.5 는 무연(SAC305) 쪽입니다.

QS-KS-001 §3.3 은 유연 라인과 무연 라인의 **용해로·주조 금형·계량기구 분리 운용**을
의무화하고 **교차 사용을 금지**합니다. 즉 이 조성은 **생산할 수 없는 제품**입니다.

이 값은 원래 ML 학습용 합성 데이터의 목표값이었고, 편차 계산 기준선으로만 쓰입니다.
다만 화면과 문서에서는 "성분 목표값" 으로 표시되어 제품 규격처럼 읽혔습니다.

### 요청

- [ ] 시스템을 **합금 계열별**로 나눌까요? (SAC305 / Sn63Pb37 / … 각각의 목표값·편차 임계)
- [ ] 우선 어느 합금을 대상으로 할까요? 생산량이 가장 많은 계열부터 넣는 것이 좋습니다.
- [ ] 편차 임계(Sn ±2.0 / Ag ±0.3 / Cu ±0.1)도 계열별로 다시 정해야 합니다.
      참고로 QS-KS-001 의 규격 폭은 **Ag 2.8~3.2 → ±0.2**, **Cu 0.4~0.6 → ±0.1** 입니다.
      현재 Ag 임계 ±0.3 은 **규격 폭보다 넓어** 규격을 벗어나도 경고가 안 뜹니다.

> ⚠ Ag 임계가 규격보다 느슨한 것은 이 3건 중 **가장 시급한 항목**입니다.
> 규격 이탈품이 경고 없이 통과합니다.

## 3. 설비 온도 경고 255°C — **정상 조업 온도보다 낮습니다**

| | 값 | 출처 |
|---|---|---|
| **시스템** | 255°C 초과 시 경고 | `equipment.temp_warn_c` |
| **WS-KS-001 WS-02** 용해로 | 유연 **340 ± 20°C** / 무연 **400 ± 20°C** | `[현장확정]` 잠정치 |
| **WS-KS-001 WS-05** 주탕 | 유연 **280 ± 15°C** / 무연 **330 ± 15°C** | `[현장확정]` 잠정치 |
| **WS-KS-001 WS-05** 금형 예열 | 100 ~ 150°C | `[현장확정]` 잠정치 |

### 무엇이 문제인가

**정상 조업 중인 용해로가 항상 경고 상태로 표시됩니다.** 유연 기준 320°C 만 되어도
255°C 를 넘습니다.

경고가 상시 켜져 있으면 아무도 보지 않게 되고, 진짜 이상이 생겼을 때 묻힙니다.

또 현재 DB 에는 **설비의 계열(유연/무연)·공정 구분이 없습니다.** 단일 임계값
하나로는 용해로·주조기·압출기를 함께 감시할 수 없습니다.

### 요청

- [ ] `equipment` 에 **설비 유형**(용해로/주조기/압출기 등)과 **계열**(유연/무연)을 추가할까요?
- [ ] 유형·계열별 경고 상하한을 정해 주십시오. 잠정치 기준이면 예를 들어
      용해로(유연) 320~360, 용해로(무연) 380~420 처럼 **범위**가 됩니다.
      현재 시스템은 **상한 하나만** 봅니다 — 하한 미달(예: 승온 부족)은 감지하지 못합니다.
- [ ] 하한도 감시할까요? WS-02 는 "설정 온도까지 승온" 을 관리 항목으로 두고 있습니다.

## 참고 — 잠정치 취급

WS-KS-001 제10장은 조업 조건 **12항목을 `[현장확정]` 잠정치**로 명시하고, 시행일로부터
3개월 실측 후 Rev.1 에서 확정한다고 밝히고 있습니다. 위 온도값도 여기 포함됩니다.

문서가 같은 장에서 이렇게 못박고 있어 그대로 따릅니다.

> 잠정치는 "지키지 않아도 되는 값" 이 아니다. 확정 전이라도 본 표준서에 기재된 값은
> 준수 대상이다.

**AI Agent 는 이 값들을 답할 때 `[현장확정]` 표시를 함께 인용합니다.** 잠정치를
확정값처럼 말하지 않도록 원문 표시를 그대로 살렸습니다.
