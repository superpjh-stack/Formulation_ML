## 0. 한 장 요약

**요청은 셋입니다. 승인이 없으면 AI Agent 는 현재대로 "준비 중"(HTTP 501)을 유지합니다.**

| # | 요청 | 성격 | 승인 주체 | 미승인 시 |
|---|---|---|---|---|
| **1** | **CR-ARCH-001** — LLM 추론에 외부 API 사용 | 보안 정책 변경 | CISO · 주관기관 | 501 유지 |
| **2** | **CR-DB-007** — DB 테이블 8종 신설 + pgvector 설치 | 기술 변경 | 도입기업 | 501 유지 |
| **3** | **코퍼스 확보** — 현장 문서 4종 제공 | **도입기업 실무** | 도입기업 | RAG 기능 불가 |

**3번이 가장 급합니다.** 1·2번은 승인 절차이지만 3번은 문서를 만드는 일이라 리드타임이 가장 깁니다.
개발로 해결되지 않습니다.

### 왜 지금 이 요청이 올라오는가

사업계획서는 RAG 기반 AI Agent 를 구축목표 5개 중 **2개**로 삼았습니다
(`RAG` 23회 · `AI Agent` 57회 등장). 그런데 **설계 산출물 16종 전체에 `RAG` 가 0회**입니다.

원인은 구조입니다. SF-AD2 요구사항정의서가 **"화면 44개 = 요구사항 44건"** 1:1 구조라,
**화면이 없는 기반 항목**(Vector DB · 문서 임베딩 · LLM 계층)은 요구사항 목록에 자리가
없었습니다. 기반이 빠지자 AI Agent 8건이 전부 **"선택"** 으로 분류됐고, 구현 단계에서
501 로 남았습니다.

**즉 사업계획서의 핵심 목표가 설계 단계에서 누락된 것이며, 이 문서는 그것을 되돌리기 위한 요청입니다.**

## 1. 요청 1 — CR-ARCH-001 : LLM 추론에 외부 API 사용

### 1.1 무엇을 바꾸려는가

| | 현행 | 변경 후 |
|---|---|---|
| SF-TD2 §6 주석 | "클라우드(AWS/Azure) 비사용 — 사내 on-premise 구성으로 데이터 보안 강화" | "애플리케이션·DB·ML 서빙은 사내 on-premise 유지. **LLM 추론만 외부 API 사용** — 송출 데이터는 허용목록으로 제한하고 전량 감사 기록" |
| 외부 서비스 표 | GitHub · Let's Encrypt · 사내 SMTP (3종) | + **LLM API** (질의응답 · 문서 임베딩) |
| 네트워크 구성도 | — | **아웃바운드 egress 경로 명시** |

### 1.2 이 요청이 건드리는 보안 약속

사업계획서 **p.60 §9.2 산업보안조치 이행계획**에 다음이 있습니다.

> "RAG 기반 AI Agent 는 내부 데이터만 접근 가능한 **폐쇄형 구조**로 설계하고, 사용 로그를 기록·관리"

**외부 API 는 엄밀한 의미의 폐쇄형이 아닙니다.** 이 문서는 그 사실을 감추지 않고,
**부분 완화에 대한 명시적 승인**을 요청합니다.

### 1.3 그럼에도 요청하는 근거 — 사업계획서 안에 반대 방향 근거가 있습니다

| 근거 | 위치 | 내용 |
|---|---|---|
| 클라우드 예산이 이미 편성됨 | 사업비 §4.7 | **클라우드 서비스 이용료 36,000천원**(1,000천원 × 36월) |
| 클라우드 AI 플랫폼이 이미 편성됨 | S/W 구입비 | **「클라우드 AI 플랫폼(Agent, ML)」 30,000천원** |
| 클라우드가 기본값이었음 | p.55 | "CLOUDE SERVR 이용이 아닌 **자체 서버 요청 시**…" — 온프레미스는 도입기업의 **선택지**였습니다 |
| GPU 미편성 | p.20 · SF-TD2 §2.1 | AI 서버 8 vCPU / 16GB, **GPU 없음**. 로컬 LLM 은 **추가 하드웨어 구매**가 필요합니다 |

**정리하면**: 사업계획서는 클라우드 AI 사용을 예산으로 승인받았고 GPU 는 편성하지 않았습니다.
로컬 LLM 을 택하려면 **승인된 예산에 없는 하드웨어를 새로 사야 합니다.**

### 1.4 비용

월 4,400건(입고·출하 Agent 기준) 산정치입니다.

| 모델 등급 | 월 비용 | 편성 예산(1,000천원/월) 대비 |
|---|---|---|
| 경량 | 약 5.3만원 | **19배 여유** |
| 표준 | 약 15.9만원 (프롬프트 캐싱 시 10.9만원) | **6배 여유** |
| 고급 | 약 26.5만원 | **3.7배 여유** |

**추가 예산이 필요하지 않습니다.**

### 1.5 승인과 함께 확보해야 할 보완 조치 5건

폐쇄형 완화를 상쇄하기 위해 다음을 **함께** 승인해 주시기 바랍니다.

| # | 조치 | 설명 |
|---|---|---|
| ① | **필드 단위 허용목록** | 테이블·컬럼 단위로 송출 가능 항목을 사전 지정. **`suppliers.name` · `shipments.customer` · `claims.customer` 는 절대 금지**. LOT·공급사·고객사 식별자는 **가역 별칭으로 치환**해 전송 |
| ② | **송출 전량 감사** | 외부로 보낸 프롬프트 원문과 받은 답변을 `agent_runs` 에 기록. **보존 90일 후 본문 삭제** — 1년 보관은 그 자체가 유출 표면이 됩니다 |
| ③ | **벤더 서면 조항** | "입력 데이터 **학습 미사용** + **최소 보존**" 계약 조항 확보 |
| ④ | **월 비용 상한** | API 사용료 상한선 지정 및 초과 시 자동 차단 |
| ⑤ | **방화벽 정책 변경** | SF-TD2 §1.2 UFW 아웃바운드 규칙에 LLM API 엔드포인트만 화이트리스트 |

### 1.6 되돌릴 수 있습니다

`LLMProvider` 어댑터로 추상화해 두었습니다. **나중에 로컬 LLM 으로 전환할 때
애플리케이션 코드는 바뀌지 않습니다.** GPU 조달이 이뤄지면 설정 변경만으로 회귀합니다.

### 1.7 영향 범위

| 구분 | 내용 |
|---|---|
| 산출물 개정 필요 | SF-TD2 §1.2·§3.2·§6 · SF-AD2 NFR-S 계열 · SF-OS1(외부 API 장애 대응) · SF-TI3(메뉴얼) |
| 코드·DB | **신규 모듈만.** 기존 **18테이블 · 107엔드포인트 · 44화면 변경 0건** |

## 2. 요청 2 — CR-DB-007 : 테이블 8종 신설

| 항목 | 내용 |
|---|---|
| 신규 테이블 | **8개** (18 → **26**) |
| 기존 테이블 변경 | **0건.** ALTER 없음 |
| 신규 확장 | `CREATE EXTENSION vector` — **pgvector 설치 선행 필요** |
| 마이그레이션 | 신규 Alembic 리비전 1개. 기존 4개 리비전 **수정 없음** |

**신규 테이블**: 대화 세션 · 메시지 · 근거(citation) · 실행로그 · 피드백 · 추천이력 · 문서원본 · 문서청크(벡터)

### 2.1 pgvector 를 쓰는 이유

사업계획서 **p.20 HW 명세가 이미 `PostgreSQL + pgvector` 를 지정**했습니다
(Vector DB 서버 1대 · AI 서버 1대 편성). 설계서가 이를 옮기지 않았을 뿐입니다.

기술적으로도 별도 벡터 DB 보다 적합합니다 — **인용이 이 시스템의 생명선이라,
문서 청크와 원본이 같은 DB 에 있어야 근거를 신뢰할 수 있습니다.**

### 2.2 보안 이행계획과의 연결

사업계획서 p.60 §9.2-5 가 **"사용 로그를 기록·관리"** 를 보안 이행계획으로 명시했습니다.
따라서 **Agent 로그 저장(`agent_runs`)은 선택 기능이 아니라 보안 요구사항입니다.**

FE-RT-42 *화면* 은 선택으로 두더라도, **저장은 입고·출하 Agent 와 같은 릴리스에 포함**해야 합니다.

## 3. 요청 3 — 코퍼스 확보 (도입기업 실무) 🔴 **가장 시급**

### 3.1 현재 상태 — 색인할 문서가 없습니다

사업계획서 p.18 이 Vector DB 대상으로 지목한 문서와 실제 보유 현황입니다.

| 사업계획서가 지목한 문서 | 현재 |
|---|---|
| 작업표준서 | DB 39행 중 **본문이 담긴 것 1행** |
| 배합 레시피 | **파일 0건** |
| 품질 기준서 | 최소 시드 수준 |
| 검사 지침서 | **파일 0건** |
| 클레임 대응 매뉴얼 | **파일 0건** |

**문서 없이 벡터 인덱스를 만들면 "근거를 찾지 못했습니다"만 반복합니다.**

### 3.2 프로젝트 산출물로 대체할 수 없습니다

`docs/산출물/` 16종(요구사항정의서·아키텍처설계서·테스트결과서 등)이 있지만
**이것은 프로젝트 산출물이지 현장 지식이 아닙니다.**

"자재 입고 기준이 뭐야" 라는 현장 질문에 설계서 문장을 근거로 답하면
**그럴듯하지만 틀린 답**이 나옵니다. 따라서 색인 대상에서 **제외**했습니다.

### 3.3 요청 사항

| 우선순위 | 문서 | 대상 화면 | 형태 |
|---|---|---|---|
| 1 | **작업 표준서** (공정별) | 입고·출하 | 기존 화면(`기준정보관리 › 작업 표준`)으로 직접 등록 가능 |
| 2 | **검사 지침서** | 출하 | 문서 파일 |
| 3 | **클레임 대응 매뉴얼** | 출하 | 문서 파일 |
| 4 | **자재 기준서** | 입고 | 문서 파일 |
| 5 | 배합 레시피 | 배합(선택) | 문서 파일 |

> **1번은 지금 바로 가능합니다.** 시스템에 이미 작업 표준 등록 화면과 버전 관리가 있습니다.
> 별도 개발 없이 현장 문서를 옮겨 넣기만 하면 그날부터 색인 대상이 됩니다.

### 3.4 문서가 없어도 되는 부분

**RAG 가 필요한 질문은 소수입니다.** 사업계획서 p.19 가 직접 적은 예시 질문 4개를
분석한 결과 **RAG 로 답해야 할 것이 0개**였습니다 — 전부 정형 데이터 조회로 답합니다.

| p.19 예시 질문 | 답하는 방식 |
|---|---|
| "이 LOT 의 불량 원인은?" | DB 조회 + 규칙 |
| "이 조건에서 배합비 최적값은?" | 기존 최적화 AI 호출 |
| "최근 불량이 가장 많이 발생한 공정은?" | DB 집계 |
| "이 제품의 공정 이력을 추적해줘" | DB 조인 |

따라서 **문서 확보가 늦어져도 입고·출하 Agent 의 상당 부분은 동작합니다.**
다만 "작업 표준이 어떻게 되어 있나" 같은 질문은 문서 없이 답할 수 없습니다.

## 4. 승인 전까지의 상태

**AI Agent 8화면은 현재 `HTTP 501`("준비 중")을 반환하며, 승인 전까지 그대로 유지됩니다.**

| 항목 | 상태 |
|---|---|
| 기존 44화면 | **정상 동작. 영향 없음** |
| 기존 107 엔드포인트 | **변경 0건** |
| v1 수용 게이트 | **영향 없음** — 현행 계약(api-contract §8.10)과 동일하게 동작 |

API 키가 설정되지 않으면 시스템은 **정상 기동하되 Agent 만 501** 을 반환합니다.
44화면 중 36화면이 Agent 와 무관하므로 서비스 전체가 멈추지 않습니다.

> **조용한 501 은 만들지 않습니다.** 기동 시 경고 로그를 남기고, 화면에는
> "아직 구성되지 않았습니다"를 명시합니다. 장애를 "준비 중"으로 위장하지 않습니다.
