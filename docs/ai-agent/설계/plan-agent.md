## 0. 이 문서를 쓴 이유 (한 문단)

AI Agent 8화면은 현재 전부 `501 Not Implemented` 다. 근거는 SF-AD2 가 이 8건을 **선택**으로
분류했다는 것 하나다. 그런데 **사업계획서는 이 8건 중 일부를 사업의 핵심 목표로 명시한다.**
사업계획서 원문에서 `RAG` 는 **23회**, `AI Agent` 는 **57회** 등장하고, 스마트공장 구축 목표 5개 중
**⓵ 입고·보관**과 **⓷ 포장·출하**가 정면으로 *"RAG 기반 AI Agent"* 다. AI 대상 3공정 중 **2개**다.
반면 **설계 산출물 16종(SF-AD1~SF-OS2) 전체에서 `RAG` 는 0회**이고, `Vector`·`LLM`·`pgvector`·
`LangChain`·`벡터` 도 **전부 0회**다 (실측: `grep -c` 16파일).

즉 **사업계획서의 핵심 목표가 분석·설계 단계에서 통째로 누락됐고, 그 결과 "선택"으로 밀렸다.**
이 문서는 (A) 그 불일치를 표로 확정하고, (B) 8화면을 재명세하고, (C) **답할 수 없는 질문의 처리**를
규정하고, (D) **Agent 가 말해도 되는 값 / 말하면 안 되는 값**을 못박는다.

## A-3. 왜 이렇게 됐는가 (원인 추정 — 비난이 아니라 기록)

SF-AD2 는 **화면 44개 = 요구사항 44건 1:1** 구조로 작성됐다. 화면으로 그릴 수 있는 것만 요구사항이
됐고, **인프라(Vector DB)·데이터 자산(문서 임베딩)·모델 계층(LLM)** 처럼 화면이 없는 항목은
요구사항 목록에 자리가 없었다. 그래서 Agent 는 "화면 8개"로만 남았고, 그 8개를 떠받칠 기반이
전부 빠진 채로 남으니 **구현 불가 → 선택** 으로 밀리는 게 자연스러운 귀결이었다.

### A-4.1 "화면은 선택, 저장은 필수" — 42 의 단서

Agent 를 켜는 순간 **질문·답변·근거·응답시간이 어딘가에 남아야 한다.** 사업계획서 p.60 은
이것을 9.2 **산업보안조치 이행계획**에 넣었다. 그리고 결정 2 에 따라 **질문이 외부 LLM API 로
나간다** — 무엇이 나갔는지 기록이 없으면 사고 시 조사가 불가능하다.

→ **`agent_logs` 테이블(CR-DB-002)은 FE-RT-10·20 과 같은 릴리스에 들어간다.**
FE-RT-42 **화면**은 선택으로 남고 계속 501 이어도 되지만, **기록은 그렇지 않다.**
이 둘을 분리하는 것이 이 결정의 요점이다.

### B-0.1 답변 출처 4분류 — 이 문서 전체의 기본 어휘

모든 질문은 **답이 어디서 나오는지**로 분류한다. Agent 는 답을 만들기 전에 이 분류를 먼저 정한다.

| 코드 | 이름 | 원천 | 근거 표기 |

| **[D]** | **비정형 문서** | Vector DB 문서 청크 (**CR-DB-007 선행 필요**. 현재 저장소 없음) | `문서명 · 버전 · 절 번호` |
| **[M]** | **계산·모델** | 기존 API 재사용 — `POST /predict` · `POST /recommend` · `GET /suppliers/{code}/stats` · `GET /deviation/*` · `GET /process/performance` | `모델명 · 학습일 · 입력값 전체` |

> **CR-DB-007 승인 전까지 [D] 로 분류되는 모든 질문은 [X] 로 강등된다.** 이건 임시조치가 아니라 계약이다.

### B-0.3 RBAC (5역할) — 공통 기준

| 역할 | 10 | 15 | 20 | 38 | 39 | 40 | 41 | 42 |

### B-0.7 **외부 LLM API 채택 — 확정 (2026-08-26)** · 8화면 전체에 걸리는 전제

LLM 은 **외부 API** 를 쓴다. 제공자 선정은 아키텍트 소관이므로 이 문서는 특정하지 않는다.
다만 **외부 API 라는 사실 자체가 화면 명세를 바꾼다.** 세 가지가 따라온다.

#### (1) 공정 데이터가 사내 밖으로 나간다 — 사업계획서 p.60 과 정면 충돌

사업계획서 p.60 9.2 산업보안조치는 이렇게 적었다:

> *"데이터관리시스템 및 AI 모델 데이터는 내부 서버 또는 보안 클라우드에 저장하여 외부 유출 방지.
> **RAG 기반 AI Agent는 내부 데이터만 접근 가능한 폐쇄형 구조로 설계**하고, 사용 로그를 기록·관리"*

**외부 API 는 "폐쇄형 구조"가 아니다.** 이건 기획이 임의로 넘어갈 수 있는 사안이 아니다.

| 항목 | 처리 |
|---|---|
| 결함 등록 | **`DEF-AG-011`** — 사업계획서 p.60 "폐쇄형 구조" ↔ 외부 LLM API 채택 불일치 |
| 필요 조치 | **`CR-ARCH-001` 에 포함**: (a) 외부 전송 허용 데이터 범위 화이트리스트 (b) 도입기업 정보보호책임자(CISO) 승인 (c) 제공자와의 학습 미사용(zero-retention) 계약 확인 |
| **화면 요구** | **모든 Agent 화면 헤더에 외부 전송 고지 배지를 상시 노출한다** (§B-0.7-(4)) |
| 전송 금지 데이터 | 개인정보(`users.username`·`email`·`audit_logs.ip_address`) · 고객사 실명(`shipments.customer`·`claims.customer`) — **마스킹 후 전송.** 근거: p.60 "데이터 반출 기준" |

> **고객사 실명 마스킹은 출하 Agent(FE-RT-20)의 핵심 제약이다.** 질문이 *"삼성전자 클레임 알려줘"*
> 면 그 문자열이 이미 외부로 나간다. 프롬프트에 붙이는 **조회 결과**만 마스킹해서는 부족하다 —
> **질문 원문도 마스킹 대상**이며, 마스킹 실패 시 전송을 중단한다. 상세는 FE-RT-20 §5.

#### (2) 느리다 — NFR-P 게이트를 다시 잡아야 한다

SF-AD2 NFR-P 에는 **Agent 항목이 아예 없다** (`DEF-AG-009`). 인접 게이트는 이렇다:

| 기존 게이트 | 값 |
|---|---|
| NFR-P-01 일반 조회 | ≤ 2초 |
| NFR-P-02 ML 예측 | ≤ 3초 |
| NFR-P-03 배합 최적화 | ≤ 5초 |

외부 LLM 왕복 + RAG 검색 + SQL 집계를 합치면 **5초로는 안 된다.** 본 문서가 제안하는 값:

| 항목 | 제안 게이트 | 근거 |
|---|---|---|
| **Agent 응답 (NFR-P-06 신설 제안)** | **≤ 15초** | 외부 API 왕복 실측 필요. 아키텍트 확정 대상 |
| 클라이언트 타임아웃 | **30초** | ts-types.md §7.1 의 **10초는 Agent 에 적용할 수 없다** — 정상 응답을 오류로 만든다 |
| 진행 표시 | **경과 초 카운터 + 단계 표시** (`조회 중 → 근거 수집 → 답변 생성`) | 15초 무표시는 멈춘 것으로 보인다 |

> ⚠ **`ts-types.md` §7.1 의 Agent 타임아웃 10초는 이 결정과 모순된다.** 계약 수정 필요 —
> **`CR-API-002` (신규 제안)**. 확정 전까지 화면은 계약값을 따르고, 10초 초과는 §B-0.4 문구로 처리한다.

#### (3) 비용이 든다 — 호출당 과금

| 항목 | 처리 |
|---|---|
| 과금 단위 | 토큰. **질문 1건 = 실비용 1건.** 새로고침·재전송이 그대로 돈이다 |
| 화면 요구 | **전송 중 재전송 차단**(§B-0.5)은 UX 가 아니라 **비용 통제**다 |
| 화면 요구 | **예시 질문 칩은 클릭 시 입력창을 채우기만 하고 자동 전송하지 않는다** — 오클릭 과금 방지 |
| 화면 요구 | 질문 1,000자 상한(§B-0.5)은 **입력 토큰 상한**이기도 하다 |
| 기록 | `agent_logs` 에 **토큰 수·추정 비용 컬럼**을 둘 것을 제안 (`CR-DB-002`). 없으면 비용 폭주를 사후에도 못 본다 |
| **금지** | 사용자가 묻지 않은 질문을 화면이 **자동으로 미리 호출**하는 것 (프리페치·자동 요약). 돈이 새고, 사용자가 요청하지 않은 답이 화면에 생긴다 |

#### (4) API 장애 시 거동 — **8화면 공통 상태 처리 (§B-0.4 에 추가)**

외부 의존이므로 **우리가 통제할 수 없는 실패 모드**가 생긴다. 전부 명시한다.

| 상황 | HTTP | 화면 문구 (그대로 쓴다) | 추가 동작 |
|---|---|---|---|
| **LLM 제공자 장애** | **503** | `"AI 응답 서비스에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요."` | 재시도 버튼. **질문은 입력창에 그대로 남긴다** |
| **호출 한도 초과 (rate limit)** | **429** | `"현재 요청이 많아 답변을 생성할 수 없습니다. 잠시 후 다시 시도해 주세요."` | 재시도 버튼 + **자동 재시도 금지** (비용) |
| **응답 시간 초과** | — (클라이언트) | `"응답 시간이 초과되었습니다. 질문을 좁혀서 다시 물어보세요."` | **부분 답변을 만들지 않는다.** 스트리밍 중 끊겨도 받은 조각을 답으로 확정하지 마라 |
| **외부 전송 차단 (마스킹 실패)** | **422** | `"질문에 외부로 보낼 수 없는 정보가 포함돼 있습니다. 고객사명·담당자명을 빼고 다시 물어보세요."` | 전송하지 않는다. **차단 사실을 `agent_logs` 에 기록** |
| **월 예산 소진** (운영 정책) | **503** | `"이번 달 AI 사용 한도에 도달했습니다. 관리자에게 문의하세요."` | 관리자 연락처는 `system_settings` 에서 읽는다 |
| **LLM 은 응답했으나 근거 0건** | **200** | §C-1 문구 | **답변 본문을 렌더링하지 않는다** — 이게 §C 의 핵심이다 |

> **장애 시 캐시된 이전 답변을 대신 보여주지 마라.** 질문이 다르면 답도 다르다.

### 6. 수용 기준 (QA 시험 문장)

1. 질문을 전송하면 **실제로 `POST /api/v1/agents/receiving` 요청이 발생**하고 본문에 `{question}` 이 담긴다 (네트워크 탭 확인).

6. 예시 질문 칩을 클릭하면 **입력창만 채워지고 요청은 발생하지 않는다** (네트워크 요청 0건).
7. 서버가 **429** 를 반환하면 `"현재 요청이 많아…"` 문구가 나오고 **자동 재시도가 발생하지 않는다** (네트워크 탭에 재요청 0건).
8. 서버가 **503** 을 반환하면 **입력창의 질문이 그대로 남아 있다** (다시 타이핑할 필요 없음).

### 6. 수용 기준

1. *"Ag 3.2% 공급사 A 사용 시 최적 비율은?"* 전송 시 `POST /agents/mixing` 요청이 발생하고, 응답의 `recommended_ratios` 4값 **합이 정확히 100.0** 일 때만 결과 카드가 그려진다.
2. 응답 합계가 `99.9` 또는 `100.1` 이면 카드가 **그려지지 않고** 오류 메시지가 나온다.

5. `optimization_success:false` 응답에서 **Sn 55.0 또는 70.0 같은 경계값이 추천으로 표시되지 않는다.**
6. 답변 어디에도 **`R² 0.874` / `0.87`** 문자열이 없다 (§D-2).

### 6. 수용 기준 (QA 시험 문장)

1. *"LOT-2026-0412 출하해도 되나?"* 전송 시 `POST /agents/shipping` 요청이 발생하고, [C] 판정 카드에 **합격선 `70점` 이 문자열로 표시**된다.
2. `quality_score` 가 `null` 인 `pending` LOT 을 물으면 **판정 카드가 그려지지 않고** "판단할 수 없습니다" 문구가 나온다.
3. 존재하지 않는 LOT 을 물으면 **404 문구**가 나오고, 답변 본문이 생성되지 않는다.
4. `matched_lots` 가 빈 배열이면 **표가 렌더링되지 않는다** (헤더만 있는 빈 표 0개).
5. 질문에 고객사 실명을 넣고 전송하면, **네트워크 요청 본문 또는 서버 로그에 실명이 남지 않는다** (치환 확인).
6. 사전에 없는 고객사명을 넣으면 **422 로 차단**되고 외부 요청이 발생하지 않는다.
7. `viewer` 로 로그인해 클레임 처리 이력을 물으면 **"접근 권한이 없습니다"** 가 나온다 (데이터가 답변에 섞이지 않는다).
8. *"다음 주 납기 맞출 수 있어?"* 를 전송하면 **날짜·건수 등 숫자가 없는** §C-2 납기 문구가 나온다.

10. 답변에 **`R² 0.874`·`0.87`** 문자열이 없다 (§D-2).

# C. 답할 수 없는 질문의 처리 — **이 문서의 핵심**

> **제1원칙: 지어내지 않는다.**
> 이 프로젝트는 웨이브 C 에서 `MOCK_*` 하드코딩과 `setTimeout` 지연연출을 전부 걷어냈다.
> **Agent 가 근거 없는 답을 내면 그게 그대로 되살아난다.** 그것도 더 나쁜 형태로 —
> 하드코딩은 코드를 읽으면 보이지만, LLM 이 지어낸 문장은 **읽어도 진짜와 구분되지 않는다.**
>
> 그래서 이 절의 규칙은 권고가 아니라 **게이트**다.

## C-0. 판정 순서 — Agent 는 답하기 전에 이 순서를 밟는다

```
질문
 ├─1. 권한 확인 ──── 대상 테이블 권한 없음 → §C-4 권한 거부 (❌ [X] 아님)
 ├─2. 외부 전송 확인 ─ 마스킹 실패 → §B-0.7-(4) 422 차단
 ├─3. 원천 확인 ──── 원천 없음 → §C-2 답할 수 없음  ← **여기서 멈춘다**
 ├─4. 파라미터 확인 ─ 부족 → §C-5 되묻기 (❌ 기본값 채우기 아님)
 ├─5. 조회·계산 ──── [S] SQL / [D] 문서 / [M] 모델
 ├─6. 근거 확인 ──── sources[] == 0 → §C-1 근거 없음  ← **답변 억제**
 └─7. 답변 + 근거 렌더 (§C-3)
```

**3번과 6번이 다르다는 점이 중요하다.**
3번은 *"물어본 것을 저장하지 않는다"* — 데이터 모델의 공백.
6번은 *"저장은 하는데 이 조건에 해당하는 행이 없다"* 또는 *"LLM 이 근거 없이 답을 만들었다"*.
**문구가 다르고 사용자가 취할 행동도 다르다.** 하나로 합치지 마라.

## C-1. 근거 없는 답변 — **`sources[]` 가 비면 답변을 렌더링하지 않는다**

| 규칙 | 값 |
|---|---|
| 판정 | `sources.length === 0` |
| 동작 | **`answer` 본문을 화면에 그리지 않는다.** 아래 문구로 **대체**한다 |

**화면 문구 (그대로 쓴다)**

> **근거를 찾지 못해 답변하지 않았습니다.**
> 질문에 해당하는 데이터를 시스템에서 찾지 못했습니다. 근거 없는 답변은 표시하지 않습니다.
> 기간이나 대상(LOT·공급사·고객사)을 좁혀서 다시 물어보세요.

**금지 사항**

| 금지 | 이유 |
|---|---|
| `answer` 를 **회색으로 흐리게** 표시 | 여전히 읽힌다. 안 그리는 것과 다르다 |
| `"참고용입니다"` 를 붙여 표시 | 면책 문구는 지어낸 내용을 진실로 만들지 않는다 |
| 근거를 **나중에 붙이겠다**며 표시 | v1 에서 영원히 안 붙는다 |
| **부분 근거로 전체 답변** | 근거가 1건인데 답변이 5문장이면 4문장은 지어낸 것이다 → §C-3-(3) |

### C-2.3 표준 문구 — **화면이 정확히 무엇을 말해야 하는가**

**공통 골격**: `무엇을 못 하는지` + `왜 못 하는지` + `대신 무엇이 가능한지`.
**숫자를 하나도 넣지 않는다.** 숫자가 들어가는 순간 그것이 답으로 읽힌다.

| 대상 | 문구 (그대로 쓴다) |
|---|---|
| **재고 잔량** (10) | **"원재료 재고 잔량은 답할 수 없습니다."** 현재 시스템은 입고 수량만 기록하고 출고·소요를 기록하지 않아 잔량을 계산할 수 없습니다. 입고 이력 조회는 `입고 이력(/receiving/history)` 화면에서 가능합니다. |
| **원재료→LOT 추적** (10) | **"원재료가 어느 LOT 에 사용됐는지는 답할 수 없습니다."** 입고 데이터와 생산 LOT 을 연결하는 기록이 없습니다. 생산 LOT 의 성분 분석 결과는 `성분 분석(/receiving/components)` 에서 확인할 수 있습니다. |
| **납기·지연** (20) | **"납기 및 지연 위험은 답할 수 없습니다."** 출하 데이터에 납기일이 저장되지 않습니다. 실제 출하 이력(출하 일시·수량·고객사)은 `출하 관리(/shipping/list)` 에서 확인할 수 있습니다. |
| **불량 유형·발생 공정** (38·40) | **"불량 유형과 발생 공정은 답할 수 없습니다."** 품질 데이터에는 점수와 합격 여부만 저장되며, 불량의 종류나 어느 공정에서 발생했는지는 기록되지 않습니다. 품질 점수와 성분 편차는 조회할 수 있습니다. |
| **생산 중량(kg)** (38·39) | **"생산 중량(kg)은 답할 수 없습니다."** 생산 실적은 LOT 단위로만 관리되며 투입·산출 중량이 저장되지 않습니다. LOT 수와 수율은 조회할 수 있습니다. |
| **설비 진동·전력** (38·39) | **"설비 진동과 전력 사용량은 답할 수 없습니다."** 현재 수집되는 설비 데이터는 상태·온도·가동시간입니다. |
| **원가·수익** (39) | **"원가 및 수익 데이터는 답할 수 없습니다."** 시스템에 단가·원가 정보가 저장되지 않습니다. |
| **문서 원문** (전 화면) | **"작업표준서 등 문서 내용은 답할 수 없습니다."** 문서 검색 기능은 아직 구축되지 않았습니다. 표준 공정 조건(온도·시간 범위)은 `공정 조건(/process/conditions)` 에서 확인할 수 있습니다. |

> **"대신 무엇이 가능한지"를 반드시 붙인다.** 이것이 44화면 시스템과 Agent 를 잇는 다리다.
> Agent 가 못 하는 일을 **할 수 있는 화면으로 넘겨주는 것**까지가 이 화면의 책임이다.
> 라우트는 실재하는 것만 쓴다 — 없는 화면으로 보내면 그것도 지어내기다.

### C-2.4 "조회 결과 0건" 은 [X] 가 아니다 — 구분해서 말한다

| 상황 | 문구 |
|---|---|
| **원천 없음** ([X]) | §C-2.3 표준 문구 — *"…는 답할 수 없습니다"* |
| **원천 있음 · 결과 0건** | *"2026년 8월 1일~26일 기간에 조건에 맞는 LOT 이 **없습니다**. (조회: lots · status='fail' · 0행)"* — **근거를 그대로 붙인다.** 0건도 답이다 |

**"없습니다"와 "답할 수 없습니다"를 섞어 쓰지 마라.** 전자는 데이터가 있고 결과가 0이라는 뜻이고,
후자는 애초에 물어볼 수 없는 것이라는 뜻이다. 사용자가 취할 행동이 다르다.

## C-3. 근거(citation) 표시 규칙

### C-3.1 `SourceRef` 구조 — 본 문서 제안 (`DEF-AG-010`, 아키텍트 확정 필요)

계약(`§8.10`)은 `sources[]` 의 **항목 구조를 정의하지 않았다.** `string[]` 로 두면 근거가
자유 문장이 되고, 자유 문장은 검증할 수 없다. **타입으로 강제한다.**

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `kind` | `'table' \| 'document' \| 'model'` | Y | §B-0.1 의 [S]/[D]/[M] |
| `ref` | string | Y | `kind=table` → 테이블명(`lots`) · `document` → 문서명+절 · `model` → 모델명(`gradient_boosting`) |
| `filter` | string | N | 적용 조건 (`status='fail' AND date >= '2026-08-01'`) |
| `row_count` | number | `table` 일 때 Y | 집계에 쓰인 **행 수** |
| `period` | string | N | 기준 기간 (`2026-08-01 ~ 2026-08-26`) |
| `version` | string | N | `document` 버전 · `model` 학습일 |
| `screen` | string | N | 같은 데이터를 볼 수 있는 라우트 (`/quality/list`) |

### C-3.2 어떤 답에 어떤 근거를 붙이는가

| 답의 종류 | 필수 근거 | 예시 |
|---|---|---|
| **[S] 숫자·건수·비율** | `kind=table` · `ref` · `filter` · **`row_count`** · `period` | `lots · status='fail' · 12행 · 2026-08-01~08-26` |
| **[S] 단건 조회** (LOT 상세) | `kind=table` · `ref` · 식별자 | `lots·quality·components · LOT-2026-0412` |
| **[D] 문서 인용** | `kind=document` · `ref`(문서명+**절 번호**) · **`version`** | `품질기준서 §3.2 · v2` |
| **[M] 예측 점수** | `kind=model` · `ref`(모델명) · **`version`**(학습일) · **입력값 전체** | `gradient_boosting · 2026-08-20 학습 · 입력 Sn 62.1/Ag 3.0/Cu 0.5/Pb 34.4/250℃/45분` |
| **[M] 배합 추천** | 위 + **경계 조건** + `optimization_success` | `Sn 55~70·Ag 1~5·Cu 0.1~1.5·Pb 25~45 · 수렴 성공` |
| **[M] 피처 중요도** | `kind=model` + **"전역 중요도이며 개별 LOT 의 인과가 아님"** 병기 | §D-2 |
| **표준 공정 조건** | `kind=table` · `process_conditions` · **`version` + `active`** | `process_conditions · SAC305 · v2 · 현행` |

### C-3.3 절대 규칙 6개

1. **근거 0건 → 답변 렌더링 금지** (§C-1).
2. **문장 단위 대응.** 답변의 각 사실 문장은 `sources[]` 중 하나로 되짚을 수 있어야 한다. 근거 1건으로 5문장을 쓰지 않는다.
3. **`row_count` 를 반드시 표시한다.** *"불량 12건"* 의 근거가 `12행`이 아니면 그 숫자는 신뢰할 수 없다.
4. **기간을 반드시 표시한다.** 기간 없는 집계는 검증 불가능하다. 사용자가 기간을 안 줬으면 **전체 기간임을 명시**한다.
5. **[M] 은 입력값 전체를 표시한다.** 예측 점수만 있고 입력이 없으면 재현할 수 없다.
6. **테이블 근거를 문서처럼 말하지 마라.** `process_conditions` 를 읽고 *"작업표준서에 따르면"* 이라고 쓰면 거짓이다 (FE-RT-15 Q5).

### C-3.4 렌더링 형태

**기본 접힘.** 답변 아래 `▼ 근거 N건` 한 줄. 클릭하면 펼쳐진다.
**단 `kind=model` 근거는 기본 펼침** — 예측·추천은 입력값을 봐야 판단할 수 있다.
`screen` 이 있으면 **해당 화면으로 가는 링크**를 단다. Agent 답을 44화면에서 직접 확인할 수 있어야 한다.

## C-5. 파라미터가 부족한 질문 — **되묻는다. 기본값으로 채우지 않는다**

*"지금 배합비 최적값 추천해줘"* (사업계획서 p.19 시나리오 2번) 에는 공급사도 성분도 없다.

| 금지 | 이유 |
|---|---|
| `SUP_A` 를 기본값으로 써서 답한다 | **사용자는 자기가 SUP_A 기준 답을 받았다는 걸 모른다.** 조용한 실패의 교과서적 형태 |
| 목표값(`SN_TARGET=62.0` 등)으로 채워 답한다 | 목표값은 편차 계산 기준이지 입력 기본값이 아니다 |
| 최근 LOT 값을 몰래 가져다 쓴다 | 근거에 나타나지 않으면 사용자는 알 수 없다 |

**되묻기 규칙**

| 항목 | 값 |
|---|---|
| 형태 | **선택 칩** (자유 입력 아님) — 오타·비용 낭비를 막는다 |
| 개수 | 한 번에 **1개 질문만**. 3개를 한꺼번에 물으면 대화가 취조가 된다 |
| 문구 | `"어느 공급사 원료 기준으로 계산할까요?"` + 칩 `SUP_A` `SUP_B` `SUP_C` |
| 비용 | 되묻기는 **LLM 호출 없이** 프론트에서 처리할 수 있으면 그렇게 한다 (§B-0.7-(3)) |
| 예외 | 사용자가 명시적으로 *"아무거나"* 라고 하면 → **선택한 값을 답변과 근거에 명시**하고 진행 |

## C-6. "정확도"를 답할 수 없다 — FR-AG-05 원문과의 의도적 불일치

SF-AD2 FR-AG-05 는 *"AI Agent 호출 로그, 응답 시간, **정확도** 추적"* 을 요구한다.
**셋 중 정확도만 계산할 수 없다.**

| 필요한 것 | 있는가 |
|---|---|
| 답변의 정답 라벨 | ❌ 없음 |
| 사용자 피드백(좋아요/싫어요) | ❌ 계약에 없음 (plan-g3 §G9-2 "공통 계약 누락"에 이미 기록됨) |
| 추천 적용 후 실측 품질 | ❌ `agent_recommendations` 부재 (§C-2.2 #12) |

| 선택지 | 판정 |
|---|---|
| LLM 자기 확신도를 정확도로 표시 | 🔴 **금지** — 근거 없는 숫자 (FE-RT-40 `confidence` 와 동일 문제) |
| 응답 성공률(2xx 비율)을 "정확도"로 표시 | 🔴 **금지** — 성공률은 정확도가 아니다. **이름을 바꿔 부르는 것도 지어내기다** |
| **정확도를 표시하지 않는다** | ✅ **본 문서 채택** |
| 대체 지표 표시 | ✅ 병행 — **`근거없음 비율`**(`status='no_evidence'` / 전체). 이건 실제로 계산된다 |

→ **`DEF-AG-020`**: FR-AG-05 의 "정확도 추적"은 **v1.1 범위에서 충족 불가**.
피드백 수집(👍/👎)을 추가하는 `CR-API-004` 가 선행되어야 한다. **도입기업 보고 대상.**

## C-7. 0행 상태에서 집계 숫자를 만들지 않는다

41·42 는 저장소가 없어 **영구히 0행**이다. 이때 요약 카드가 `0회`·`0ms`·`0%`·`0원` 을 표시하면
**"측정했더니 0이었다"** 로 읽힌다. 실제로는 **측정한 적이 없다.**

| 상황 | 표시 |
|---|---|
| 501 (미구현) | **`—`** + 배너. 숫자 금지 |
| 200 · 0행 (구현됐고 데이터 없음) | **`0`** + `"표시할 이력이 없습니다."` — 이건 진짜 0이므로 허용 |

**`0` 과 `—` 를 구분하는 것이 이 프로젝트의 기본 문법이다.**
동일 규칙이 이미 계약에 있다 — `*_delta` 는 전일 데이터가 없으면 `null` 을 보내고
프론트가 배지를 숨긴다. *"**0 으로 채우지 마라 — 0%p 변화와 구분이 안 된다**"* (api-contract §8.2).

# D. 하드 룰 준수 규칙 — Agent 가 말할 때 반드시 지켜야 할 값

> Agent 는 **44화면과 같은 사실을 말해야 한다.** 화면에서 `70점`이 합격선인데 Agent 가
> `75점`이라고 하면, 둘 중 하나가 틀린 게 아니라 **시스템 전체의 신뢰가 무너진다.**
> 이 절의 값은 goal.md 2.3 하드 비즈니스 룰이 정본이며, **UI · API · Agent 세 곳에서 동일하게 강제된다.**

## D-1. Agent 가 반드시 지켜야 할 값 (goal.md 2.3)

| # | 룰 | 값 | Agent 답변에서의 의미 |
|---|---|---|---|
| 1 | **품질 합격선** | **70점** | 점수를 말할 때 **항상 `(기준 70점)` 병기.** `70` 미만은 **불합격**이라고 명시. `quality.passed = (score >= 70)` |

| 상황 | 행동 |

## D-2. 🔴 **말하면 안 되는 값 목록** — Agent 가 인용하면 허위가 되는 수치

### D-2.1 최우선 — 모델 성능

| 값 | 정체 | Agent 의 처리 |
|---|---|---|
| **`R² 0.874`** (`0.8739`) | **합성 시드 데이터** 성능. `data/raw/generate_sample.py` 가 신호/노이즈 비를 우리가 정해서 만든 **시뮬레이션 결과**다 | 🔴 **실데이터 성능으로 인용 금지.** *"R² 0.87 달성"* 은 **허위다** (api-contract §7.4) |
| **`R² 0.782`** | **SF-TI2 실데이터 실측값** | ✅ **실데이터 성능을 말해야 하면 이 값을 쓴다** |
| **`R² 0.85`** | SF-AD1 의 **희망 목표치** | ⚠ *"달성했다"* 고 말하지 마라. SF-TI2 가 *"추가 실데이터 축적 시 달성 가능"* 으로 조정했다 |
| **`R² 0.60`** | SF-AD2 NFR-P-05 **합격선** | ✅ 계약 게이트. *"기준 0.60 을 충족한다"* 는 참 |
| `R² 0.627` · `0.588` | CLAUDE.md 의 **구버전 샘플** 수치 | 🔴 인용 금지 — 현행 아티팩트와 다르다 |
| `R² 0.51` | **Ridge 베이스라인** | ⚠ 인용 가능하나 **"선형 베이스라인"** 임을 반드시 병기 |

**Agent 표준 문구 (모델 성능을 물었을 때)**

> 현재 서비스 모델은 `gradient_boosting` 입니다.
> **실데이터 기준 결정계수(R²)는 0.782** 이며, 계약 기준치(0.60 이상)를 충족합니다.
> *(근거: SF-TI2 시스템전환결과서 실측)*

**금지 문구**: *"R² 0.87 을 달성했습니다"* · *"목표 0.85 를 초과했습니다"* · *"정확도 87%"*
(**R² 는 정확도가 아니다** — 결정계수를 백분율 정확도로 바꿔 말하는 것도 허위다)

## D-5. QA 체크리스트 — D절 전체를 그대로 시험한다

1. Agent 답변 전문에 문자열 **`0.874`·`0.8739`·`0.87`** 이 **0회** 나타난다.
2. 모델 성능을 물으면 **`0.782`** 가 나오고 **"실데이터 기준"** 문구가 함께 나온다.
3. **`정확도 87%`** 같은 백분율 표현이 R² 자리에 나타나지 않는다.
4. 점수를 말하는 모든 답변에 **`70`** 이 기준으로 병기된다.
5. 배합비를 말하는 모든 답변에서 **4성분 합이 정확히 `100.0`** 이다.
6. 온도를 말하는 답변에 **`255`** 경고 기준이 병기된다.
7. 편차를 말하는 답변에 **임계값(`2.0`/`0.3`/`0.1`)** 이 병기된다.
8. §D-2.2 의 16개 값이 답변에 **나타나지 않는다** (특히 `kg`·재고 수량·납기일).
9. §D-2.3 의 6개 금지 표현이 답변에 **나타나지 않는다**.
10. 사내 데이터 근거 없이 **솔더 공정 일반론**을 답하는 사례가 0건이다 (§C-1 로 억제).
11. `optimization_success:false` 응답에서 **비율값이 추천으로 표시되지 않는다**.
12. `ridge` 가 배합 추천 모델 선택지에 **없다**.
