## 0. 이 설계가 지키는 한 문장

**화면은 서버가 실제로 준 것만 그린다. 안 준 것은 안 그린다. 못 그리는 이유를 대신 그린다.**

이 프로젝트가 걷어낸 조용한 실패 4종은 전부 UI 레이어에서 발생했다.

| 걷어낸 것 | 어느 화면 | UI 가 한 거짓말 |
|---|---|---|
| `setTimeout(1100)` + 미리 쓴 답변 | FE-RT-10·15·20·38 | 지연이 계산을 뜻한다 |
| `● 온라인` 초록 점 · "연결된 데이터 5종" | FE-RT-10·20·38 | 초록이 연결을 뜻한다 |
| 로컬 state 만 바꾸는 채택/기각·읽음 처리 | FE-RT-40·41 | 눌렀으니 저장됐다 |
| 하드코딩 수치가 박힌 분석 카드 | FE-RT-15·39·40·41 | 카드 안 숫자는 측정값이다 |

**네 가지 모두 "표현이 근거보다 앞선" 사고다.** 그래서 이 설계의 모든 규칙은 §B(근거 표시)와
§C(신뢰 상태)에서 파생된다. 대화 UI·스트리밍·칩은 그 두 절의 하위 규칙이다.

## A. 대화형 UI 패턴 카탈로그

### A.0 왜 8화면이 다 같은 채팅창이면 안 되는가 — 세 가지 실측 근거

**1. 세 화면은 자연어로 표현할 수 없는 필수 입력을 갖는다.**
`POST /agents/analysis` 의 필수 필드는 `topic` 이고 `date_from`/`date_to`/`lot_id` 가 선택이다.
`POST /agents/decision` 의 필수 필드는 `lot_id` 하나다. 이것을 채팅으로 받으면
*"6월 불량 LOT 분석해줘"* 라는 문장에서 날짜 경계와 LOT 을 **LLM 이 추측**해야 한다.
추측이 틀려도 화면은 알 수 없다 — 새로운 조용한 실패다.
드롭다운은 `GET /api/v1/lots?status=fail` 실데이터로 채워지므로 **존재하지 않는 LOT 을 고를 수 없다.**
이것은 UI 취향이 아니라 환각 차단 장치다.

**2. 두 화면에는 Agent 가 없다.**
FE-RT-41·42 는 `GET` 이다. 생성도 추론도 없다. 저장된 행을 페이지네이션해서 보여준다.
여기에 입력창을 달면 존재하지 않는 대화 상대를 발명하는 것이다.

**3. 계약상 대화는 아직 대화가 아니다.**
5개 `POST` 요청 본문 중 대화 맥락을 나르는 필드는 `/agents/query` 의 `context?` **하나뿐이고,
그 의미가 계약에 정의돼 있지 않다** (현 구현이 그래서 보내지 않는다).
세션 ID·이전 턴 배열·대화 저장 테이블이 전부 없다 (CR-DB-002 미승인).

> **결론: 서버는 상태가 없다(stateless). 화면이 "대화"처럼 보이면 안 된다.**
> 이어지는 문답 로그는 **각 턴이 서로 독립인 단발 질의의 목록**이다.
> 두 번째 질문에 *"방금 그 LOT 말이야"* 라고 쓰면 서버는 아무것도 모른다.
> 이 사실을 화면이 §A.1 의 **컨텍스트 고지 규칙**으로 명시한다.

### A.1 패턴 4종

#### P1 — 문답 로그 (Single-turn log)

겉모습은 채팅이지만 **의미는 "질문·답변 쌍의 시간순 목록"** 이다.

```
┌ PageShell ──────────────────────────────────────────────────────────────┐
│ PageHeader  「입고 AI Agent」 / 부제                                      │
│ [PendingBanner]  ← 501 인 동안만                                          │
│ ┌───────────────────────────────────┬──────────────────────┐            │
│ │ Section 「문답」                    │ Section 「이 Agent가  │            │
│ │ ┌───────────────────────────────┐ │  다루는 범위」        │            │
│ │ │ AgentTurnLog  (role="log")    │ │  · 지원 질의 유형     │            │
│ │ │                               │ │    (읽기 전용 — §E)   │            │
│ │ │           ┌── 질문 버블 ────┐ │ │  · 데이터 범위        │            │
│ │ │           └─────────────────┘ │ │    (서버 제공 시만)   │            │
│ │ │  ┌─ AgentAnswer ───────────┐  │ │                      │            │
│ │ │  │ 신뢰 배지 + 답변 본문    │  │ │  ← 서버가 아무것도    │            │
│ │ │  │ 근거 요약 줄             │  │ │     주지 않으면 이    │            │
│ │ │  │ CitationList             │  │ │     열 자체를 렌더    │            │
│ │ │  └─────────────────────────┘  │ │     하지 않는다 (G7)  │            │
│ │ │  ⋮ (시간순 누적 · 스크롤)      │ │                      │            │
│ │ └───────────────────────────────┘ │                      │            │
│ │ ┌ AskBox ───────────────────────┐ │                      │            │
│ │ │ textarea · 카운터 · [전송/취소]│ │                      │            │
│ │ │ 컨텍스트 고지 한 줄            │ │                      │            │
│ │ └───────────────────────────────┘ │                      │            │
│ └───────────────────────────────────┴──────────────────────┘            │
└─────────────────────────────────────────────────────────────────────────┘
```

* 그리드 `1fr 260px` · gap 20 (design-standards §1.3 좌우 2분할). 1280 폭에서 문답 열 686px 확보.
* 우측 열에 넣을 서버 데이터가 없으면 **1열로 접는다.** 빈 사이드 카드를 만들지 않는다.
* 로그 영역 `minHeight: 320` · `overflowY: auto` · 새 턴 도착 시 하단 스크롤.
* **컨텍스트 고지** — `AskBox` 하단 캡션 11/400 `T.textMuted`:
  *"질문은 한 건씩 독립으로 처리됩니다. 이전 질문 내용은 다음 질문에 이어지지 않습니다.
  대화는 새로고침하면 사라집니다."*
  → 계약에 세션/멀티턴이 생기면 이 문장 **한 줄만** 교체된다 (§A.3).

#### P2 — 폼 → 리포트 문서 (Form → Report)

조건을 고르고 **한 번** 요청해서 **문서 하나**를 받는다. 누적되지 않는다.

```
PageHeader
[PendingBanner]
FilterBar   [분석 주제*] [LOT] [기간 시작] [기간 종료] [분석 요청]
Section 「분석 결과」
  └ AgentAnswer  variant="report"
      신뢰 배지 · 리포트 본문(장문, max-width 68ch) · 근거 요약 줄 · CitationList
      (charts[] 는 원소 스키마 확정 전까지 렌더하지 않는다 — G8)
```

* 결과는 **직전 1건만** 보여준다. 이력 목록을 만들지 않는다 — 리포트 목록 `GET` 이 계약에 없다.
* 재요청하면 이전 결과를 교체한다. 교체 전 확인 없음(파괴적 저장이 아니다).
* 요청 조건은 결과 상단에 **되짚어 표시**한다: `주제: 8월 불량 LOT 원인 · 기간 2026-08-01~08-31`.
  조건 없이 떠 있는 리포트는 무엇에 대한 답인지 3초 안에 판단할 수 없다.

#### P3 — 폼 → 정형 결론 (Form → Verdict)

응답이 **자유 문장이 아니라 고정 스키마**다: `root_causes[]` · `recommendations[]` · `confidence`.
장문 리포트(P2)와 시각적으로 구분해야 한다 — 읽는 방식이 다르다(훑기 vs 정독).

```
PageHeader
[PendingBanner]
FilterBar   [대상 LOT*(불량 LOT 실데이터)] [원인 분석]
Section 「분석 결과」
  ├ 대상 요약 줄   LOT-2026-0142 · 2026-08-12 · 품질 62.4 [불합격]   ← lib/quality.ts 배지
  ├ grid 2열 gap 20
  │   ├ 「추정 원인」   ol · 각 항목 뒤 인라인 근거 마커
  │   └ 「개선 방안」   ol · 각 항목 뒤 인라인 근거 마커
  ├ 신뢰 배지 + confidence 표기            ← §C.4 confidence 규칙
  └ CitationList (두 열 공통 근거)
```

* `confidence` 는 **신뢰 상태(§C)와 다른 축이다.** 모델이 자기 답에 매긴 점수이지 근거의 유무가 아니다.
  두 개를 한 배지에 섞지 마라 — `lib/quality.ts` 가 합격/등급 두 축을 분리한 것과 같은 이유다.
* `root_causes` 와 `recommendations` 가 **둘 다 비면 답변이 아니다** → §C 상태 3(답변 불가).
  빈 `ListCard` 두 장을 나란히 그리는 현 구현은 "분석했는데 원인이 없다"로 오독된다.

#### P4 — 목록·표 (List)

Agent 없음. 저장된 행을 조건으로 걸러 본다. **기존 `DataTable` 로 충분하다.**

```
PageHeader
[PendingBanner]
FilterBar / PillFilter
Section 「… (N건)」
  └ DataTable  또는  그룹 헤더 표 (41만)
     Pagination
     각주 (스키마 미정의 고지)
```

### A.2 화면별 배정과 근거

### A.3 멀티턴은 언제 켜지는가 — 전환 스위치 하나

지금 P1 은 **단발 문답 로그**다. 계약이 아래 셋을 모두 갖추면 그때 대화가 된다.

| 필요한 것 | 현재 | 없으면 생기는 거짓말 |
|---|---|---|
| 요청에 세션/이전 턴 필드 (`context` 의미 확정) | ❌ 미정의 | 화면이 이어진 척하는데 서버는 매번 처음 듣는다 |
| 대화 저장 테이블 | ❌ CR-DB-002 미승인 | "이력"이 새로고침에 사라지는데 이력처럼 보인다 |
| 답변이 어느 턴을 참조했는지 표시 | ❌ 없음 | 근거 추적이 턴 경계에서 끊긴다 |

**설계 대응**: `AgentTurnLog` 에 `multiTurn: boolean` prop 하나를 둔다.
`false`(v1) — 고지 문구 A + 각 턴 사이 옅은 구분선(`T.border` 1px)으로 **독립임을 시각화**.
`true` — 고지 문구 B + 구분선 제거 + 턴 연결선. **컴포넌트 교체 없이 prop 만 뒤집는다.**

### A.4 P1 안의 "결과 슬롯" — 답변 카드가 표·수치를 품는 방식

FE-RT-15 의 `recommended_ratios?` 와 FE-RT-20 의 `matched_lots[]` 는
**답변 텍스트와 같은 카드 안**, 근거 요약 줄 **위**에 놓는다.

```
┌ AgentAnswer ─────────────────────────────┐
│ [근거 3건]                    14:22       │  ← 신뢰 배지 (§C)
│ 답변 본문 …                               │
│ ┌─ 결과 슬롯 (선택) ──────────────────┐   │  ← ratios 카드 / matched_lots 미니표
│ │ Sn 61.850  Ag 3.120  Cu 0.480 …    │   │
│ └────────────────────────────────────┘   │
│ 근거 3건 · lots 214건 · 모델 gradient_… │  ← 근거 요약 줄 (§B.3)
│ ▸ 근거 (3)                                │  ← CitationList (§B.4)
└──────────────────────────────────────────┘
```

* 슬롯은 **해당 필드가 있을 때만** 존재한다. 빈 카드 금지 (G7).
* 슬롯 안 수치는 서버 값 그대로. 성분 3자리·품질 2자리 (`lots.*_ratio DECIMAL(6,3)` · `quality.score DECIMAL(5,2)`).
* `matched_lots[]` 미니표는 **최대 5행 + "출하 관리에서 전체 보기" 링크**. 페이지네이션을 답변 안에 넣지 않는다.
* 합격/불합격 배지는 `lib/quality.ts` `passBadgeFromServer()` (G5).
* 합계 검산(`sum ≈ 100 ± 0.05`)이 어긋나면 슬롯에 amber 인라인 경고를 붙이되 **값을 고치지 않는다.**

세로 리듬 24 · 카드 그리드 20 · 카드 내부 8~12 (design-standards §1.2). **새 레이아웃 원시 요소를 만들지 않는다.**

### A.6 P1-S — 범위 고정 문답 (입고 FE-RT-10 · 출하 FE-RT-20)

**외부 LLM 을 쓰기로 결정됐다.** 이 결정이 P1 설계를 한 군데 바꾼다.

맨 채팅창은 두 가지를 동시에 악화시킨다.
1. **조건을 모델이 추측한다.** *"최근 공급사 편차 어때?"* → "최근"이 30일인지 90일인지,
   공급사가 셋 다인지 하나인지 **모델이 정한다.** 화면은 무엇으로 계산됐는지 모른다.
2. **범위가 없으면 전송량이 정해지지 않는다.** 외부로 나갈 데이터의 상한이 프롬프트 작성 시점까지
   결정되지 않는다.

그래서 FE-RT-10·20 은 **P1 위에 조건 바를 얹은 P1-S** 로 간다.
조건 바는 UI 장식이 아니라 **외부 전송 범위의 사용자 선언**이다.

```
┌ Section 「문답」 ───────────────────────────────────────────────┐
│ ┌ ScopeBar (FilterBar 재사용) ───────────────────────────────┐ │
│ │ [공급사 ▾ SUP_A] [기간 2026-06-01 ~ 06-30] [성분 ▾ Sn]      │ │  ← 입고
│ │ [고객사 ▾ CUST-A] [출하 LOT ▾ LOT-2026-0142]                │ │  ← 출하
│ └────────────────────────────────────────────────────────────┘ │
│   AgentTurnLog …                                                │
│ ┌ AskBox ────────────────────────────────────────────────────┐ │
│ │ textarea …                                       [전송]     │ │
│ │ 이 범위로 질문합니다 · SUP_A · 2026-06-01~06-30 · Sn        │ │  ← 범위 되짚기
│ │ 질문과 위 범위의 데이터가 외부 AI 서비스로 전송됩니다 [전송 항목 보기] │ │
│ └────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

| 규칙 | 내용 |
|---|---|
| 조건 값의 출처 | **실데이터만.** 공급사 = `SUPPLIER_CODES`(`_g1/ui.tsx`, SUP_A/B/C 3사) · 출하 LOT·고객사 = `GET /shipments` 응답 distinct. 하드코딩 목록 금지 |
| 조건 → 요청 | 자유 문장과 **함께 별도 필드로** 전송한다 (§A.7 계약 요청). 문장 안에 녹여 보내지 않는다 |
| 조건 → 답변 | 각 턴 카드에 **그때의 범위를 동결해 표시**한다. 조건 바를 바꿔도 과거 턴의 표시는 변하지 않는다 |
| 조건 미선택 | 기간만 필수. 나머지 미선택 = "전체". 전송 범위 캡션이 `전체 공급사` 로 바뀐다 — 조용히 넓히지 않는다 |
| 기간 상한 | 조건 바에서 막는다(예: 최대 12개월). 상한값은 서버 `capabilities` 가 준 값만 쓰고, 없으면 상한을 걸지 않고 **경고도 하지 않는다**(발명 금지) |

**왜 두 화면을 폼(P2/P3)으로 바꾸지 않았나** — 출하 담당자는 고객 전화를 받으면서 묻는다.
질문의 형태가 미리 정해지지 않는다. 폼은 예측된 질문만 답한다. 반대로 입고는 조건이 명확하므로
폼이 더 정확하다 — 그래서 **양쪽 다 만족하는 지점이 "범위는 폼, 질문은 문장"** 이다.
그리고 두 화면이 같은 컴포넌트(`ScopeBar` prop 만 다름)를 쓰므로 시각 언어가 갈라지지 않는다.

## B. 근거 표시 (Citation)

### B.0 외부 LLM 이 이 절의 무게를 바꾼다

RAG + Rule + 오케스트레이터에서 **문장을 쓰는 것은 외부 모델**이다.
모델은 `lots` 를 조회한 적 없어도 *"6월 SUP_A 의 Sn 편차는 평균 1.8%p 로 안정적입니다"* 를
**문법적으로 완벽하게** 쓴다. 사람은 이 문장만 보고 진위를 구분할 수 없다.

> **그래서 근거 표시는 답변의 부록이 아니라, 답변을 답변으로 만드는 조건이다.**
> 근거 없는 문장은 "근거가 빠진 답변"이 아니라 **"답변이 아닌 문장"** 이다. 그렇게 보여야 한다.

이 절이 답할 질문은 하나다 — **작업자가 3초 안에 "믿어도 되나"를 판단할 수 있는가.**

### B.1 근거 3종 — 데이터 모델

현 계약은 `sources: string[]` **문자열 배열**뿐이다. 문자열로는 종류·건수·기간·신선도를
구분할 수 없고, 검증 동선(§B.6)을 만들 수 없다. **`Citation` 객체로의 승격을 요청한다.**

```
Citation =
  │ kind: "dataset"                          ← 정형 데이터
  │   table       "lots"                      필수
  │   row_count   214                         필수  ← 건수 없는 데이터 근거는 근거가 아니다
  │   date_from   "2026-06-01"                선택
  │   date_to     "2026-06-30"                선택
  │   filters     { status: "fail" }          선택
  │   as_of       "2026-08-26T14:20:11+09:00" 필수  ← 언제 조회한 값인가
  │   route       "/quality/lots?status=fail" 선택  ← 서버가 줄 때만 (§B.6)
  │
  │ kind: "document"                          ← 문서
  │   doc_id      "WORK_STD-012"              필수
  │   title       "용융 공정 작업표준"          필수
  │   section     "§3.2"                      선택
  │   revision    "2026-03-11"                필수  ← 개정일 없는 표준은 인용 불가
  │   excerpt     "용융 온도는 240~260°C…"     필수  ← §B.4 강등 규칙
  │
  │ kind: "model"                             ← 모델
  │   model       "gradient_boosting"         필수
  │   version     "v3"                        필수
  │   trained_at  "2026-08-01"                필수  ← "언제 학습된 것인가"가 신뢰의 핵심
  │   route       "/system/models"            선택
```

응답에는 `citations: Citation[]` 와 함께 `evidence_level: "grounded"|"weak"|"none"` 및
`weak_reason?: string` 을 요청한다 (§C.2 — **판정은 서버가 한다**, G4).

**하위 호환**: `citations` 가 없고 `sources: string[]` 만 오면 —
각 문자열을 `kind:"unknown"` 근거로 그리되 **초록 배지를 주지 않는다.**
종류·건수·기간을 모르는 근거는 검증할 수 없으므로 §C 상태 2(경고)로 떨어뜨린다.
문자열을 파싱해서 테이블명·건수를 **추출하려 시도하지 마라** — 그것이 발명이다.

> ⚠ **문서 근거를 낼 저장소가 없다.** DB 18테이블(db-schema §2) 어디에도 문서·표준·매뉴얼
> 코퍼스가 없다. `kind:"document"` 는 RAG 코퍼스 테이블이 생긴 뒤에야 실제로 도착한다.
> **UI 는 지금 그려 두되, 도착하지 않는 동안 자리를 차지하지 않는다** (G7).

### B.2 배치 결정 — 인라인이냐, 블록이냐, 접기냐

**결론: 3층 구조. 블록이 정본이고, 인라인은 v1 에서 켜지 않으며, 접기는 4건째부터만.**

| 층 | 무엇 | 소요 시선 | 접히나 |
|---|---|---|---|
| **L1 신뢰 배지** | 색 + 숫자 (`근거 3건`) | ~0.5초 | ❌ 절대 |
| **L2 근거 요약 줄** | 한 줄 요약 — 종류·건수·기간 | ~3초 | ❌ 절대 |
| **L3 근거 목록** | `CitationList` 카드 | 필요할 때 | 4건째부터만 |

**왜 인라인 마커(`[1]`)를 v1 에서 켜지 않는가 — 이것이 이 절에서 가장 중요한 판단이다.**

인라인 마커는 *"이 문장은 저 근거에서 나왔다"* 는 **주장**이다.
그 주장이 참이려면 **문장 ↔ 근거 매핑(span)** 이 응답에 있어야 한다.
현 계약에는 없다. 없는 상태에서 화면이 `[1]` 을 붙이면 —
**근거를 보여주는 UI 가 그 자체로 지어낸 값이 된다.** 이 프로젝트가 걷어낸 실패와 정확히 같은 형태다.
(과거: 미리 쓴 답변에 "연결된 데이터" 초록 점을 붙였다. 지금: 임의 문장에 `[1]` 을 붙인다.)

> **설계**: `AgentAnswer` 는 `spans?: {start, end, citation_index}[]` prop 을 받는다.
> 서버가 주면 인라인 마커가 켜지고, 없으면 **렌더되지 않는다.** 컴포넌트 교체 없이 전환된다.

**왜 전부 접지 않는가.** 접힌 근거와 없는 근거는 **픽셀 단위로 같다.**
근거 유무가 3초 판단의 전부인데 그것을 클릭 뒤로 숨기면 판단 자체가 사라진다.
**L2 요약 줄은 어떤 경우에도 접히지 않는다.**

**왜 전부 펼치지 않는가.** 근거 8건이면 답변보다 근거가 길어진다.
→ L3 은 **상위 3건 펼침 + `근거 5건 더 보기` 버튼**. 접힌 부분에도 종류별 건수는 버튼 라벨에 남긴다:
`데이터 3 · 문서 1 · 모델 1 더 보기`.

### B.3 L2 근거 요약 줄 — 3초 판단의 실체

답변 본문 바로 아래, `CitationList` 위. 12/600 라벨 + 11.5/400 값. 한 줄, 넘치면 말줄임.

```
근거 3건 · lots 214건 (2026-06-01~06-30) · WORK_STD-012 §3.2 · gradient_boosting v3 (2026-08-01 학습)
```

구성 규칙 — **왼쪽부터 판단에 먼저 필요한 순서**:

| 순서 | 조각 | 규칙 |
|---|---|---|
| 1 | `근거 N건` | N 은 `citations.length`. **0이면 이 줄이 §B.5 로 대체된다** |
| 2 | 데이터 | `{table} {row_count}건 ({기간})` — 건수가 없으면 테이블명만. 기간이 없으면 기간을 생략(추측 금지) |
| 3 | 문서 | `{doc_id} {section}` |
| 4 | 모델 | `{model} {version} ({trained_at} 학습)` |
| 5 | 신선도 | 가장 오래된 `as_of` 가 **24시간 이상 전**이면 끝에 amber `· 조회 시각 8/25 09:12` |

**성능 수치는 넣지 않는다.** `R²`·`MAE`·`MAPE` 를 근거 줄에 인용하는 것은
`api-contract.md` §7.4 위반이다. 모델 근거는 **이름·버전·학습일까지**다.

### B.4 L3 `CitationList` — 종류별 카드 해부

목록 항목은 44화면의 카드 문법을 따른다: 1px `T.border` · radius 8 · padding 10/12 · gap 6.
왼쪽에 4px 종류 레일, 그 옆에 종류 배지(`StatusBadge`), 본문, 오른쪽에 검증 링크.

```
┌──────────────────────────────────────────────────────────────────────┐
│▎[데이터]  lots · 214건 · 2026-06-01 ~ 06-30 · status=fail   [열기 ↗] │
│           조회 2026-08-26 14:20                                       │
├──────────────────────────────────────────────────────────────────────┤
│▎[문서]   WORK_STD-012 용융 공정 작업표준 §3.2 · 개정 2026-03-11       │
│           “용융 온도는 240~260°C 를 유지하고, 260°C 초과 시…”          │
├──────────────────────────────────────────────────────────────────────┤
│▎[모델]   gradient_boosting v3 · 2026-08-01 학습            [열기 ↗]  │
└──────────────────────────────────────────────────────────────────────┘
```

| 종류 | 배지 variant | 레일 색 | 필수 표시 | 없으면 |
|---|---|---|---|---|
| `dataset` | `blue` `데이터` | `--badge-blue-text` | 테이블 · **건수** · 조회시각 | 건수 없음 → 카드에 amber `건수 미제공` · §C 상태 2 로 강등 |
| `document` | `violet` `문서` | `--badge-violet-text` | 문서ID · 개정일 · **발췌 원문** | 발췌 없음 → `원문 확인 불가` · §C 상태 2 로 강등 |
| `model` | `gray` `모델` | `--badge-gray-text` | 모델명 · 버전 · 학습일 | 학습일 없음 → `학습 시점 미상` · 강등 |
| `unknown` | `gray` `출처` | `--badge-gray-text` | 원문 문자열 그대로 | — (항상 상태 2) |

**발췌(excerpt)를 필수로 두는 이유**: 문서 ID 만 적힌 근거는 검증할 수 없다.
작업자가 `WORK_STD-012` 를 열어 볼 수 없는 자리(현장 단말)에서 ID 는 **권위의 외양**일 뿐이다.
두 줄 원문이 있으면 그 자리에서 답변과 대조된다. **발췌 없는 문서 근거는 근거로 세지 않는다.**

발췌 표기 — 11.5/1.7 `T.textSub`, 좌측 2px `T.border` 인용 레일, 최대 3줄 말줄임,
**원문 그대로**(요약·의역 금지). 큰따옴표는 원문의 일부가 아니므로 회색으로 렌더.

### B.5 근거가 **없는** 답 — 이 절의 핵심

서버가 문장은 냈는데 `citations` 가 0건인 경우다. **가장 위험한 화면 상태다** —
읽히기는 정상 답변처럼 읽히고, 틀렸을 때 아무도 알아채지 못한다.

**설계 원칙: 용기(container)를 바꾼다. 문구만 바꾸지 않는다.**

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  [근거 없음]                                        14:22
  ⓘ 사내 데이터로 확인되지 않은 문장입니다. 작업 판단의
    근거로 쓰지 마세요.
  ─────────────────────────────────────────────────────────
  6월 SUP_A 의 Sn 편차는 대체로 안정적인 편입니다. …
  ─────────────────────────────────────────────────────────
  근거를 찾지 못한 이유: 조회 범위에 해당하는 lots 행이 없음
  [범위를 넓혀 다시 묻기]   [질문 복사]
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

| 항목 | 규격 | 왜 |
|---|---|---|
| 테두리 | **1px dashed `T.border`** | 실선 카드 = 확정. 파선 = 미확정. `PendingResult` 와 같은 시각 가족 |
| 배경 | `T.surfaceSubtle` (`#F8F9FB`) | **흰 카드(`T.surface`)를 주지 않는다** (G3) |
| 배지 | `gray` · `근거 없음` | 초록은 셀 수 있을 때만 (G2). 빨강도 아니다 — 오류가 아니라 미확인이다 |
| 고지 줄 | 12/600 `T.textSub`, 본문 **위** | 읽기 전에 알아야 한다. 아래 각주는 읽히지 않는다 |
| 본문 색 | `T.textSub` (본문 `T.text` 아님) | 확정 정보와 같은 검정을 쓰지 않는다 |
| 이유 줄 | 서버 `weak_reason` **원문**. 없으면 이 줄을 렌더하지 않음 | 이유를 프론트가 지어내지 않는다 |
| 후속 동작 | `범위를 넓혀 다시 묻기`(조건 바 포커스) 또는 `다시 묻기` | 막다른 골목을 만들지 않는다 |

**금지**: 근거 0건 답변에 ① 흰 카드 ② 초록·파랑 계열 배지 ③ 접근 가능한 근거 영역
④ 복사 시 고지 문구 누락 ⑤ "출처: -" 같은 **빈 근거 자리** (G7 — 있으나 마나 한 자리가 아니라 아예 다른 용기다).

> **판별 테스트**: 화면을 1280px 캡처해 500ms 만 보여줬을 때, 근거 있는 답과 근거 없는 답이
> **서로 다른 물건으로 보이면 통과**다. 문구를 읽어야 구분되면 실패다.

### B.6 검증 동선 — 근거를 열 수 있어야 근거다

`dataset`·`model` 근거 카드 우측의 `열기 ↗` 는 **같은 조건이 걸린 실제 화면**으로 이동한다.
예: `lots · status=fail · 2026-06` → `/quality/lots?status=fail&date_from=…`.

| 규칙 | 내용 |
|---|---|
| 링크 출처 | **서버가 준 `route` 만 쓴다.** 프론트가 테이블명으로 라우트를 추측하지 않는다 |
| 추측 금지 이유 | `db-schema §2` 에서 `lots` 에 대응하는 화면은 FE-RT-02·17·21·24·34 **다섯 개**다. 프론트가 고르면 틀린 화면으로 보낸다 — 죽은 검증 동선이 검증 없음보다 나쁘다 |
| `route` 없음 | 링크를 렌더하지 않는다. 카드는 정보만 표시 |
| 새 탭 | `target="_blank"` — 답변을 잃지 않게. 대화는 메모리에만 있다 |
| `document` | 문서 뷰어 화면이 없다 → v1 은 **링크 없음**, 발췌로만 검증 |

### B.7 근거의 반출 — 복사하면 근거도 따라간다

`AgentAnswer` 의 `답변 복사` 는 본문만 복사하지 않는다.

```
[근거 3건] 6월 SUP_A 의 Sn 편차 평균은 …

근거
- 데이터 lots 214건 (2026-06-01~06-30, status=fail), 조회 2026-08-26 14:20
- 문서 WORK_STD-012 §3.2 (개정 2026-03-11)
- 모델 gradient_boosting v3 (2026-08-01 학습)

고려솔더 AI · 2026-08-26 14:22 · AI 생성 답변
```

근거 0건이면 첫 줄이 `[근거 없음] 사내 데이터로 확인되지 않은 문장입니다.` 로 나간다.
**이유**: 복사·붙여넣기는 답변이 화면 밖으로 나가는 유일한 경로다. 여기서 근거가 떨어지면
메신저에 붙은 순간 그 문장은 다시 "출처 불명의 확정 사실"이 된다 — 조용한 실패의 재발이다.

### B.8 §B 금칙 요약

| # | 금칙 |
|---|---|
| B1 | 문장↔근거 매핑(`spans`) 없이 인라인 마커를 그리지 마라 |
| B2 | `sources: string[]` 를 파싱해 테이블명·건수를 추출하지 마라 |
| B3 | 근거 요약 줄(L2)을 접거나 숨기지 마라 |
| B4 | 발췌 없는 문서 근거·건수 없는 데이터 근거를 정상 근거로 세지 마라 |
| B5 | 근거 링크를 프론트가 추측해 만들지 마라 |
| B6 | 모델 근거에 성능 수치(R²·MAE·MAPE)를 인용하지 마라 (api-contract §7.4) |
| B7 | 근거 0건 답변을 흰 카드에 담지 마라 |
| B8 | 복사 텍스트에서 근거·고지를 빼지 마라 |

## C. 신뢰 상태 — 4종의 시각 규격

### C.0 축이 두 개다 — 색을 낭비하지 않으려면

4종을 나누는 축은 **"믿을 수 있나"** 하나가 아니라 두 개다.

```
                근거 충분          근거 부족          답이 없음
              ┌─────────────┬─────────────────┬──────────────────┐
  영구        │ ① 근거 있음  │ ② 근거 약함     │ ③ 답할 수 없음    │
  (재시도 무의미)│   green     │   amber        │   gray           │
              └─────────────┴─────────────────┴──────────────────┘
  일시                    ④ 실패 · 타임아웃 · 장애
  (재시도 유효)             red
```

**③ 과 ④ 를 절대 섞지 마라.**
③ 은 *"데이터에 그 답이 없다"* — 100번 눌러도 같다.
④ 는 *"지금 서비스가 답을 못 준다"* — 30초 뒤엔 될 수도 있다.
사용자가 이 둘을 헷갈리면 ③ 에서 헛되이 재시도하거나, ④ 에서 *"데이터가 없구나"* 하고
잘못된 결론을 안고 돌아간다. **색과 문구가 이 차이를 말해야 한다.**

### C.1 4종 정의

| # | 상태 | 배지 (`StatusBadge`) | 글리프 | 용기 | 재시도 | 언제 |
|---|---|---|---|---|---|---|
| **①** | 근거 있는 답 | `green` **`근거 N건`** | `✓` | `.card` 흰 면 · 실선 `T.border` | — | `evidence_level="grounded"` |
| **②** | 근거가 약한 답 | `amber` **`근거 약함`** | `⚠` | `.card` 흰 면 + **좌측 3px `T.warning` 레일** | 조건을 바꿔 재질의 | `evidence_level="weak"` · 또는 강등 규칙(§B.4) |
| **③** | 답할 수 없음 | `gray` **`근거 없음`** / **`답변 불가`** | `—` | **파선 1px `T.border` + `T.surfaceSubtle`** | ❌ 무의미 | 근거 0건(③a) · 서버 거절(③b) |
| **④** | 실패·타임아웃 | `red` **`응답 실패`** / **`시간 초과`** | `✕` | 실선 1px `T.error` + `--badge-red-bg` | ✅ **[다시 시도]** | HTTP 4xx/5xx · 타임아웃 · 취소 |

**배지 색값은 전부 기존 `--badge-*` 토큰이다. 새 팔레트 없음.**

| variant | 글자 | 배경 | 레일/테두리 |
|---|---|---|---|
| `green` | `--badge-green-text` `#15803D` | `--badge-green-bg` `#ECFDF3` | — |
| `amber` | `--badge-amber-text` `#B45309` | `--badge-amber-bg` `#FEF6E7` | `T.warning` `--color-warning` |
| `gray` | `--badge-gray-text` `#5B6573` | `--badge-gray-bg` `#F2F4F7` | `T.border` (파선) |
| `red` | `--badge-red-text` `#B91C1C` | `--badge-red-bg` `#FEF1F2` | `T.error` `--color-error` |

**글리프는 전부 `aria-hidden`, 항상 텍스트 라벨과 함께.** 색만으로 구분되는 정보를 만들지 않는다.
글리프는 코드베이스가 이미 쓰는 문자를 재사용한다 — `⚠`(`PendingBanner`) · `—`(`DASH`) · `ⓘ`(각주).

**왜 ③ 이 회색인가.** 두 가지 이유다.
① amber 는 이미 `PendingBanner`(501)와 ② 가 쓴다. 셋이 겹치면 화면에서 가장 자주 만나는
두 상태(근거 약함 / 답 없음)가 같은 색이 된다 — 구분해야 할 것부터 뭉갠다.
② 회색은 이 코드베이스에서 이미 **"값 없음"** 의 색이다 (`DASH = "—"` · `lotStatusBadge('pending') → gray`).
답이 없는 것은 실패가 아니라 값이 없는 것이다. **정직한 거절에 빨강을 칠하면 시스템이 고장 난 것처럼 보인다.**

**왜 ③ 이 빨강이 아닌지 한 번 더** — ③ 은 이 설계가 **가장 자주 보고 싶어 하는 상태**다.
근거 없이 답하느니 답하지 않는 편이 낫다. 자주 보게 될 정상 동작에 오류색을 칠하면
사용자는 곧 그 색을 무시하기 시작하고, ④ 의 진짜 실패까지 같이 무시한다.

### C.2 상태 파생 — 서버가 정하고, 프론트는 읽기만 한다

```
④ 실패        ← HTTP 4xx/5xx · 네트워크 오류 · 타임아웃 · 사용자 취소      (최우선)
③b 답변 불가   ← answer/report/root_causes 가 전부 비었다
③a 근거 없음   ← 문장은 있고 citations.length === 0
② 근거 약함    ← evidence_level === "weak"  또는  §B.4 강등 규칙 1건 이상
① 근거 있음    ← evidence_level === "grounded" 이고 citations.length >= 1
```

| 규칙 | 내용 |
|---|---|
| **G4 재확인** | 프론트는 표본 수도 임계값도 모른다. **"약함"을 프론트가 판정하지 않는다** — 서버 `evidence_level`/`weak_reason` 이 정본 |
| 예외 1건 | §B.4 **강등**만 프론트가 한다 (발췌 없는 문서·건수 없는 데이터·`kind:"unknown"`). 이는 판정이 아니라 **표시 불가 사실의 반영**이다 |
| 강등은 한 방향 | 프론트는 등급을 **낮추기만** 한다. `weak` 를 `grounded` 로 올리는 경로는 없다 |
| `evidence_level` 없음 | ①로 가지 않는다. `citations.length >= 1` 이면 ②, 0이면 ③a |
| **501** | ④ 가 아니다. **v1 정상 경로** — `PendingBanner` + `PendingResult` (§G9-2). 501 을 빨간 실패로 그리면 "미구현"이 "장애"로 오독된다 |
| 부분 실패 | 답변은 왔는데 근거 조회만 실패 → ③a 가 아니라 ② + `근거를 불러오지 못했습니다`. 없는 것과 못 가져온 것은 다르다 |

### C.3 용기 규격 — 500ms 판별 테스트를 통과하는 값

| | ① | ② | ③ | ④ |
|---|---|---|---|---|
| 배경 | `T.surface` `#FFFFFF` | `T.surface` | `T.surfaceSubtle` `#F8F9FB` | `--badge-red-bg` `#FEF1F2` |
| 테두리 | 1px solid `T.border` | 1px solid `T.border` | **1px dashed `T.border`** | 1px solid `T.error` |
| 좌측 레일 | 없음 | **3px `T.warning`** | 없음 | 없음 |
| radius | 10 | 10 | 10 | 10 |
| padding | 14/16 | 14/16 (레일 제외) | 18/16 | 12/14 |
| 본문 색 | `T.text` | `T.text` | **`T.textSub`** | `#B42318` (기존 오류 문구색) |
| 본문 크기 | 13/1.8 | 13/1.8 | 13/1.8 | 12.5/1.6 |

세 가지 신호가 **동시에** 바뀌도록 설계했다 — 배경 면 · 테두리 종류 · 본문 색.
색각 이상이나 저조도 모니터에서 하나가 안 보여도 나머지가 남는다.

> **판별 테스트(§B.5)**: 1280px 캡처 4장을 500ms 씩 보여줬을 때 문구를 읽지 않고
> 네 장이 서로 다른 물건으로 보이면 통과.

### C.4 문구 사전 — 그대로 쓴다

문구는 QA 테스트 케이스가 된다 (design-standards §3.3 규칙과 동일).

| 상태 | 배지 라벨 | 헤더/고지 | 보조 |
|---|---|---|---|
| ① | `근거 N건` | (없음 — 근거 요약 줄이 대신한다) | — |
| ② weak | `근거 약함` | `근거가 충분하지 않습니다.` | 서버 `weak_reason` **원문**. 없으면 줄 자체를 생략 |
| ② 강등 | `근거 약함` | `근거를 확인할 수 없는 항목이 있습니다.` | `문서 발췌가 제공되지 않았습니다` 등 강등 사유 |
| ③a | `근거 없음` | `사내 데이터로 확인되지 않은 문장입니다. 작업 판단의 근거로 쓰지 마세요.` | `근거를 찾지 못한 이유: {weak_reason}` |
| ③b | `답변 불가` | `답할 수 없습니다 — 근거가 될 데이터가 없습니다.` | `조회 범위를 넓히거나 다른 조건으로 물어보세요.` |
| ④ 5xx | `응답 실패` | `error-contract` 문장 그대로 (503 → `서비스 일시 중단`) | `HTTP {status} — {서버 detail 원문}` |
| ④ 타임아웃 | `시간 초과` | `{N}초 안에 응답이 오지 않았습니다.` | `서버가 계속 처리 중일 수 있습니다. 다시 시도하면 새 요청이 나갑니다.` |
| ④ 레이트리밋 | `응답 실패` | `요청이 몰려 잠시 제한되었습니다.` | `{Retry-After}초 후 다시 시도할 수 있습니다.` |
| ④ 취소 | `취소됨` | `취소했습니다 — 서버 응답을 받지 못했습니다.` | — |

**③ 과 ④ 를 가르는 한 문장을 반드시 넣는다:**
③ → `같은 조건으로 다시 물어도 결과는 같습니다.`
④ → `잠시 후 다시 시도해 주세요.`
이 두 문장이 사용자의 다음 행동을 결정한다.

### C.5 재시도 어포던스 — ③ 에는 없고 ④ 에는 있다

| 상태 | 주 동작 | 보조 |
|---|---|---|
| ① | `답변 복사` | 근거 `열기 ↗` |
| ② | `조건 바꿔 다시 묻기` (조건 바 포커스 이동) | `답변 복사` |
| ③a | `범위를 넓혀 다시 묻기` | `답변 복사`(고지 포함 — §B.7) |
| ③b | `조건 바꿔 다시 묻기` | — · **`다시 시도` 버튼을 두지 않는다** |
| ④ | **`다시 시도`** (같은 요청 재전송) | 401 → 로그인 · 503 → `error-contract` 동작 |

* ④ 의 `다시 시도` 는 레이트리밋이면 `Retry-After` 초 동안 `disabled` + 남은 초 표시.
  카운트다운은 **실제 남은 초**다 — 진행 연출이 아니다.
* ③ 에 `다시 시도` 를 두면 그 버튼이 *"다시 누르면 답이 나올 수도 있다"* 고 말하는 셈이다. **거짓이다.**

### C.6 `confidence` 는 신뢰 상태가 아니다 (FE-RT-40)

`POST /agents/decision` 의 `confidence` 는 **모델이 자기 답에 매긴 점수**다.
근거의 존재 여부와 무관하다 — 근거 0건인데 `confidence: 0.95` 가 올 수 있고, 그것이 가장 위험한 조합이다.

| 규칙 | 내용 |
|---|---|
| 분리 표시 | 신뢰 배지(§C.1)와 **다른 줄**에. 한 배지에 섞지 마라 (`lib/quality.ts` 의 합격/등급 2축 분리와 같은 원칙) |
| 표기 | `null` 이면 **영역 자체를 렌더하지 않는다.** 0으로 채우지 않는다 |
| 범위 미정의 | 계약이 0~1 인지 0~100 인지 안 정했다 → `<= 1` 이면 백분율, 아니면 숫자 그대로 (현 구현 규칙 유지) |
| 색 | **의미색을 칠하지 않는다.** `T.text` 검정 숫자. 높은 confidence 에 초록을 칠하면 G2 위반 — 셀 수 있는 것이 아니다 |
| 함정 | ③a(근거 없음) + 높은 confidence → 화면은 ③a 로 그린다. **confidence 가 상태를 올리지 못한다** |

### C.7 §C 금칙

| # | 금칙 |
|---|---|
| C1 | `getQualityBadgeVariant()` 를 신뢰 상태에 쓰지 마라 (`{90,75,60}` — 합격선 70이 없다) |
| C2 | ③(영구)과 ④(일시)에 같은 색·같은 문구·같은 버튼을 주지 마라 |
| C3 | ③ 에 `다시 시도` 버튼을 두지 마라 |
| C4 | 501 을 ④ 로 그리지 마라 — `PendingBanner` 경로다 |
| C5 | 프론트가 `weak` 를 판정하지 마라. 강등만 하고 승격하지 마라 |
| C6 | `confidence` 로 신뢰 상태를 올리지 마라 |
| C7 | 숫자 없는 초록 배지를 만들지 마라 (G2) |
| C8 | 네 상태를 색만으로 구분하지 마라 — 배경·테두리·본문색 3신호 동시 변경 |

## D. 스트리밍 · 대기 상태

### D.0 한 줄 원칙

> **움직이는 것은 데이터가 도착할 때만 움직인다.**
> 화면의 움직임은 장식이 아니라 **신호**다. 데이터 없이 움직이면 없는 신호를 보낸 것이다.

과거 이 화면들은 `setTimeout(1100)` 뒤 미리 쓴 답을 붙였다.
점 3개가 통통 튀는 동안 **아무 요청도 나가지 않았다.** 그 애니메이션은 거짓말의 전달 수단이었다.
`components/agent/` 에 타이핑 인디케이터를 다시 만들지 않는다.

### D.1 요청 생애주기 — 하나의 상태 기계, 두 전송 방식

아키텍트가 스트리밍 여부를 판단 중이므로 **둘 다 같은 상태 기계로 흡수**한다.
분기는 `streaming: boolean` prop 하나이고, 화면 구조·문구·접근성 처리는 공유한다.

```
 idle
  │  전송
  ▼
 sending        요청 나감 (0~1초)          "요청을 보냈습니다"
  │
  ├─ streaming ──▶ 토큰 도착 중            본문이 자라남 + caret
  │                (유휴 20초 → timeout)
  │
  └─ waiting ────▶ 응답 대기               경과 초 카운터
                   (20초 → 안내 문구 교체)
                   (60초 → timeout)
  │
  ▼
 settled : grounded │ weak │ none │ error │ timeout │ cancelled
                        └────────── §C 의 ①②③④ 로 렌더 ──────────┘
```

* `sending` 과 `waiting` 은 **같은 시각 상태**다 (구분해 그리지 않는다). 상태 기계에서만 분리.
* `settled` 이후 그 턴은 **변하지 않는다.** 나중 요청이 앞선 턴을 고쳐 쓰지 않는다.
* 동시 요청 없음 — `waiting`/`streaming` 중 전송 버튼은 `취소` 로 바뀐다 (§D.5).

### D.2 비스트리밍 대기 — 무엇을 보여줄 것인가

**답: 실제로 알고 있는 것만. 그것은 "요청이 나갔다"와 "몇 초 지났다" 두 가지뿐이다.**

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  ◌  응답을 기다리는 중입니다 · 12초 경과        [취소]
     (20초 경과 시)
  ◌  응답이 예상보다 오래 걸립니다 · 24초 경과   [취소]
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

| 항목 | 규격 |
|---|---|
| 용기 | 파선 `T.border` + `T.surfaceSubtle` — **③ 과 같은 "미확정" 가족**. 흰 카드를 미리 깔지 않는다 |
| 아이콘 | `Spinner size="sm"` (기존 `components/ui/Spinner.tsx`) — **선택**. 없어도 설계가 성립한다 |
| 경과 시간 | **1초 단위 정수.** 실제 경과 시각이다 (`Date.now()` 차) — 연출이 아니다 |
| 문구 교체 | 20초 시점에 한 번. 상태는 그대로, **문장만** 바뀐다 |
| 취소 | 항상 활성 (0초부터) |
| 답변 자리 | **미리 잡지 않는다.** 스켈레톤 문장 블록 금지 — 길이를 모르면서 길이를 주장하는 것이다 |

**진행률 바(progress bar)를 쓰지 않는다.** 남은 시간을 모른다. 모르는 것을 그리면 그것이 발명이다.

### D.3 스트리밍 — 켜졌을 때의 규격

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  [생성 중 — 근거 미확정]                       [취소]
  6월 SUP_A 의 Sn 편차 평균은 1.8▌
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

| 규칙 | 내용 | 이유 |
|---|---|---|
| 용기 | 스트리밍 중에도 **파선 + `surfaceSubtle`** | 아직 확정 답변이 아니다. 완료 시 §C 등급에 따라 용기가 바뀐다 |
| 배지 | `gray` **`생성 중 — 근거 미확정`** | 초록은 근거가 확정된 뒤에만 (G2) |
| 본문 색 | `T.textSub` | 완료 시 등급에 따라 `T.text` 로 승격 |
| **근거 영역** | **스트리밍 중 절대 렌더하지 않는다** | 근거는 완결 응답에만 있다. 문장이 흐르는 동안 근거를 보이면 아직 없는 뒷받침을 있다고 말하는 것 |
| caret `▌` | 2px 블록. **토큰이 실제로 도착한 시점에만 표시.** 3초간 새 토큰이 없으면 caret 을 **멈춘다**(깜빡임 중단, 표시는 유지) | 깜빡임이 "지금 오는 중"을 뜻하게 만든다. 데이터와 무관하게 도는 애니메이션은 §D.0 위반 |
| 유휴 타임아웃 | 마지막 토큰 후 **20초** 무응답 → ④ `시간 초과` (부분 텍스트는 남긴다) | |
| 부분 텍스트 처리 | 타임아웃·취소 시 받은 만큼 남기고 `불완전한 응답입니다 — 끝까지 받지 못했습니다` 고지 | 조용히 지우면 사용자는 답을 다 받았다고 오해한다 |
| 자동 스크롤 | 사용자가 위로 스크롤한 상태면 **따라가지 않는다**. 대신 하단에 `새 내용 ↓` 버튼 | 읽는 중 화면이 끌려가는 것은 제어권 탈취 |

**전송 방식이 무엇이든 화면은 같다.** SSE 든 청크 응답이든 `AgentAnswer` 는
`streamText: string` 과 `done: boolean` 만 본다. 프로토콜은 데이터 계층에 가둔다.

**가장 중요한 금지 — 통째로 받은 텍스트를 쪼개어 흘리지 마라.**
서버가 완결 응답을 한 번에 줬는데 화면이 문자 단위로 지연 렌더링하면
그것은 스트리밍이 아니라 **§D.0 이 금지한 그 애니메이션**이다. 이름만 바뀐 재범이다.

### D.4 타임아웃 정책 — 전역 10초는 Agent 에 맞지 않는다

`ts-types.md` §7.1 은 전역 10초 타임아웃을 정했다. **LLM 응답은 수 초~수십 초다.**
10초를 그대로 적용하면 **정상 응답이 전부 ④ 실패로 그려진다** — 새로운 조용한 실패다.
내보내기(`/export`)가 이미 예외인 선례가 있다.

| 구간 | 값 | 근거 |
|---|---|---|
| 첫 응답(비스트리밍) / 첫 토큰(스트리밍) | **20초** | 이 시간 안에 아무것도 없으면 요청이 서버에 닿지 않았을 가능성 |
| 전체(비스트리밍) | **60초** | 외부 LLM + RAG 검색 왕복의 현실적 상한 |
| 유휴(스트리밍) | 마지막 토큰 후 **20초** | 스트림이 끊긴 것을 감지 |
| 문구 교체 지점 | 20초 | 상태 전이가 아니라 문장 교체 |
| 재시도 백오프 | 서버 `Retry-After` **만** 따른다 | 없으면 즉시 재시도 허용 |

> **계약 요청 D-1**: `POST /agents/*` 를 전역 10초 타임아웃의 **예외**로 명시.
> 값이 확정되기 전에는 화면이 60초를 쓰되, **타임아웃 문구에 초 수를 넣어**
> (`60초 안에 응답이 오지 않았습니다`) 어떤 상한이 적용됐는지 사용자가 알 수 있게 한다.

### D.5 취소

| 항목 | 규격 |
|---|---|
| 어포던스 | 전송 버튼이 **같은 자리에서** `취소` 로 바뀐다. 버튼을 추가하지 않는다 |
| 키보드 | `Esc` — 입력창에 포커스가 있고 요청 진행 중일 때만 |
| 구현 | `AbortController`. **실제로 요청을 끊는다.** 화면만 되돌리고 응답을 버리는 방식 금지 |
| 취소 후 | 그 턴은 ④ `취소됨` 카드로 **남는다.** 조용히 사라지지 않는다 |
| 재시도 | `취소됨` 카드에 `다시 시도` — 같은 질문·같은 범위로 **새 요청**을 보낸다 |
| 입력 복구 | 취소 시 질문 원문을 입력창에 되돌리지 않는다 (턴 카드에 남아 있다). `질문 복사`로 가져간다 |

### D.6 접근성 · 모션

| 항목 | 규격 |
|---|---|
| 대기 알림 | 대기 컨테이너 `role="status"` `aria-live="polite"`. **진입 시 1회** `"응답을 기다리는 중입니다"` |
| 경과 초 | `aria-hidden="true"` — 매초 낭독은 소음이다. 20초 문구 교체 때만 한 번 더 알린다 |
| 스트리밍 중 | 본문 영역 `aria-live="off"` — 토큰마다 읽으면 사용 불가 |
| 완료 시 | live 영역에 **짧은 요약만**: `"답변이 도착했습니다. 근거 3건."` / `"답할 수 없습니다."` / `"응답에 실패했습니다."` 본문은 포커스 이동으로 읽는다 |
| 포커스 | 완료 시 그 턴 카드로 포커스를 옮긴다 (`tabIndex={-1}` + `focus()`). 화면 끝으로 튀지 않게 |
| 로그 영역 | `role="log"` `aria-relevant="additions"` |
| `prefers-reduced-motion: reduce` | caret 깜빡임 정지(표시는 유지) · 스피너 회전 정지 · 자동 스크롤 `behavior:"auto"` |
| 모션 예산 | 이 설계에 **필수 애니메이션이 0개**다. 스피너·caret 은 전부 꺼도 정보가 보존된다 |

> `app/globals.css` 에 전역 `@media (prefers-reduced-motion: reduce)` 규칙이 아직 없다.
> **이 웨이브에서 `globals.css` 를 수정하지 않는다.** `components/agent/` 내부에서
> `window.matchMedia("(prefers-reduced-motion: reduce)")` 로 처리하고,
> 전역 규칙 추가는 별도 과제로 넘긴다 (§F.6).

## E. 입력 보조

### E.0 원칙 — 칩은 제안이 아니라 약속이다

예시 질문 칩을 누르는 사용자는 *"이건 답할 수 있는 질문이구나"* 라고 읽는다.
**못 답할 질문을 칩으로 권하면 사용자를 함정에 빠뜨린다.** 그리고 외부 LLM 은
못 답할 질문에도 **그럴듯한 문장을 반드시 만들어 낸다** — 함정이 조용히 닫힌다.

### E.1 예시 질문 — v1 은 **누를 수 없다**

현 8화면은 `EXAMPLE_QUESTIONS` 를 하드코딩하고 클릭하면 입력창에 채운다.
문구 자체는 정직하게 도출됐다(FR 원문에서). **문제는 클릭 가능하다는 사실이다.**
서버는 501 이고, 501 이 풀린 뒤에도 **어떤 질문을 답할 수 있는지 아무도 선언하지 않았다.**

| 단계 | 조건 | 렌더 |
|---|---|---|
| **v1 (지금)** | 능력 선언 없음 | **읽기 전용 목록.** `<li>` — 버튼 아님, 포커스 대상 아님. 제목 `이 Agent 가 다룰 질의 유형` · 각주 `현재는 준비 중입니다` |
| **v1.1** | `GET /agents/capabilities` 존재 | **클릭 가능한 칩.** 서버가 준 `examples[]` 만. 하드코딩 배열은 삭제 |

```
GET /agents/capabilities → {
  enabled: boolean,
  examples: [{ text, requires: ["lots","quality"] }],
  scope:   { suppliers: [...], date_max_months: 12 },
  transmit_fields: ["question","supplier","date_from","date_to","component"]
}
```

* 칩이 켜져도 **누르면 입력창에 채워질 뿐 자동 전송하지 않는다** (현 구현의 좋은 부분 — 유지).
  자동 전송은 오타 한 번에 외부 API 호출 한 번이 나가는 구조다.
* `requires` 에 있는 데이터가 현재 범위에 없으면 그 칩은 `disabled` + 사유 툴팁.
* **하드코딩 예시를 버튼으로 만들지 마라.** 그것이 이 절의 전부다.

이 문서는 `PLANNED_FEATURES`(FE-RT-20 현 구현)의 읽기 전용 목록 방식을 **8화면 공통 규격으로 승격**한다.
이미 코드베이스 안에 정답이 하나 있었다.

### E.2 외부 전송 고지 — 외부 LLM 결정에 따른 신설

질문과 조회 범위의 데이터가 **사외로 나간다.** 사용자가 이 사실을 모르면 안 된다.
동시에, 겁주는 배너를 상시로 띄우면 사용자는 사흘 만에 그것을 보지 않게 된다.

**설계: 경고가 아니라 사실로 취급한다. 두 지점에만 둔다.**

| 지점 | 형태 | 문구 |
|---|---|---|
| ① `AskBox` 하단 (상시) | 캡션 11/400 `T.textMuted` — **의미색 아님** | `질문과 선택한 범위의 데이터가 외부 AI 서비스로 전송됩니다. [전송 항목 보기]` |
| ② `전송 항목 보기` | 기존 `Modal` (width 480) | 서버 `transmit_fields` **원문 나열** + 범위 요약 + `전송되지 않는 항목` |

* **경고색(amber)을 쓰지 않는다.** amber 는 §C ② 와 `PendingBanner` 가 쓴다.
  상시 표시되는 사실 고지에 경고색을 칠하면 진짜 경고의 값이 떨어진다.
* 모달 내용은 **서버가 준 목록만.** `transmit_fields` 가 없으면 모달 대신
  `전송 항목이 아직 공개되지 않았습니다` 한 줄 — 항목을 추측해 나열하지 않는다.
* **최초 1회 동의 모달은 v1 범위 밖.** 동의를 저장할 테이블이 없다(CR-DB-002).
  저장 못 하는 동의는 ① 매번 뜨거나 ② `localStorage` 에 저장해 **동의한 척**하게 된다.
  후자는 이 프로젝트가 걷어낸 실패 유형(로컬 state 를 저장으로 위장)과 같다.

### E.3 호출을 낭비하지 않게 하는 장치 — 외부 API 는 호출당 비용이다

**프론트가 할 수 있는 일만 한다. 비용을 추정하거나 표시하지 않는다**(단가를 모른다).

| 장치 | 규격 | 근거 |
|---|---|---|
| 전송 중 재전송 차단 | 버튼 `disabled` → `취소` | §G9-2 기존 규칙 |
| 자동 전송 없음 | 칩·조건 변경·페이지 진입 어느 것도 요청을 만들지 않는다 | 요청은 **사용자의 명시적 클릭**에서만 |
| 중복 질문 확인 | 직전 턴과 **정규화 후 동일**한 질문이면 인라인 확인 한 줄: `같은 질문입니다. 다시 보낼까요? [보내기] [취소]` | 오타 재전송·연타 방지 |
| 빈/무의미 입력 차단 | 공백만·1자 → 버튼 `disabled` | 기존 규칙 유지 |
| 세션 호출 횟수 | `AskBox` 캡션에 `이번 세션 3회 요청` — **프론트가 실제로 센 값** | 지어낸 값이 아니다. 세션 한정임을 문구로 명시 |
| 범위 선축소 | §A.6 조건 바 | 전송량의 상한을 사용자가 먼저 정한다 |

* 남은 호출량·쿼터·요금을 **표시하지 않는다.** 서버가 주지 않는다 (G8).
  서버가 `X-RateLimit-Remaining` 을 주기 시작하면 그때 캡션에 붙인다.

### F.1 `AgentAnswer`

**하나의 답변 = 하나의 신뢰 상태 = 하나의 카드.** §B·§C·§D 의 시각 규격을 이 컴포넌트가 독점한다.

```ts
type AgentAnswerStatus =
  | { kind: "waiting";   elapsedSec: number; timeoutSec: number }
  | { kind: "streaming"; text: string; lastTokenAt: number }
  | { kind: "grounded";  text: string }
  | { kind: "weak";      text: string; reason: string | null; degraded: DegradeReason[] }
  | { kind: "unverified";text: string; reason: string | null }   // ③a 근거 없음
  | { kind: "refused";   reason: string | null }                 // ③b 답변 불가
  | { kind: "error";     status: number | null; message: string; retryAfterSec?: number }
  | { kind: "timeout";   timeoutSec: number; partialText?: string }
  | { kind: "cancelled"; partialText?: string };

interface AgentAnswerProps {
  variant: "answer" | "report" | "verdict";   // P1 / P2 / P3
  status: AgentAnswerStatus;
  citations: Citation[];                       // waiting·streaming 에서는 무시된다
  spans?: CitationSpan[];                      // 없으면 인라인 마커 렌더 안 함 (B1)
  slot?: React.ReactNode;                      // ratios 카드 · matched_lots 미니표 (§A.4)
  verdict?: { rootCauses: string[]; recommendations: string[]; confidence: number | null };
  scopeLabel?: string;                         // 동결된 조회 범위 (§A.6)
  requestLabel?: string;                       // P2 요청 조건 되짚기 (§A.1 P2)
  at?: string;                                 // "14:22" — 서버 시각 없으면 생략
  onRetry?: () => void;                        // ④ 전용. ③ 에 넘기면 렌더 안 함 (C3)
  onRefine?: () => void;                       // ②·③ — 조건 바 포커스
  onCancel?: () => void;                       // waiting·streaming 전용
}
```

| 책임 | 내용 |
|---|---|
| 용기 선택 | `status.kind` → §C.3 표의 배경·테두리·레일·본문색을 고른다. **여기 말고 어디서도 정하지 않는다** |

}): string;   // "SUP_A · 2026-06-01~06-30 · Sn"  |  "전체 공급사 · 2026-06"

미선택 항목은 **생략하지 않고 `전체 …` 로 명시**한다 — 조용히 넓히지 않는다 (§A.6).

`types/agent.ts` 는 §B.1 의 `Citation` · `CitationSpan` · `EvidenceLevel` · `DegradeReason` ·
`AgentAnswerStatus` 를 담는다. **계약이 확정되면 `contracts/ts-types.md` 로 승격**하고 이 파일은 재수출만 한다.

## G. 인계 — 계약 요청 종합
